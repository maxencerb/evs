`decodeScriptError` and `matchScriptError` now decode a revert, and nothing else. A provider's `-32603` answer (`Internal error`, `Remote Error`, an upstream timeout, an out-of-gas reported under that code) used to decode as `{ name: 'empty' }` and reach the `_` handler, because viem wraps every such answer in a `ContractFunctionRevertedError`. It is now `undefined` for `decodeScriptError` and rethrown by `matchScriptError`, like a rate limit or a timeout. The same goes for an error that only carries hex `data`, which used to come out as `{ name: 'unknown' }`: avalanchego's answer to a deployless result over a creation limit (the rejected code is in `data`), and viem's error for a successful result that does not fit the ABI. In the other direction, an empty revert that a node answers as `{ code: -32000, message: 'execution reverted' }` without `data` (Scroll, Sonic) used to be rethrown and is now `empty`, as on every other node. Revert data that a wallet nests under `data.originalError`, or that a node writes as `data: "Reverted 0x…"`, is now found (the first needs viem 2.47.5 or later with `readContract`: earlier versions drop the node's answer from the error they throw). The `decodeScriptError` reference page has a new section, "What counts as a revert".
