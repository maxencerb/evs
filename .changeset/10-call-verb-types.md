The types of the call verbs (`s.read`, `s.tryRead`, `s.call`, `s.tryCall`, `s.simulate` and `s.trySimulate`) take what recording takes, and say what is missing.

- **`args` is required when the function takes arguments**, as viem's `readContract` requires it. `s.read({ address, abi: erc20Abi, functionName: 'balanceOf' })` used to type-check and then throw while recording (`function "balanceOf" expects 1 argument(s), got 0`); it is now a compile error, `Property 'args' is missing`. `args` stays optional when the function takes none (`args: []` is accepted too), for an overloaded name that has an overload without arguments (the one such a call resolves to), and for an ABI that has no literal type. A wrapper whose parameter is typed `SubcallParams<abi, name>`, for a function that takes arguments, is refused by the verbs for the same reason (`No overload matches this call`), although it type-checked in 0.6.0: type the parameter with `ResolvedSubcallParams`, which requires `args`, for example `ResolvedSubcallParams<typeof erc20Abi, 'balanceOf', ViewMutability, readonly [Expr<'address'>]>`.
- **`struct: true` is a compile error on a call whose function has an unnamed output, or no output.** It used to type-check, the result being a `Tuple` with a member named `""`, and recording then threw `ABI_SHAPE` (`output #0 of "getConfig" is unnamed`). The error sits on `struct` and says why: `'evs: struct: true needs every output named': "an output of getConfig is unnamed — use the default positional result (omit struct)"`. A Solidity getter that returns a struct has one unnamed tuple output: its default result is already a `Tuple` keyed by member name.
- **The result of a call on an ABI with no literal type** (typed `Abi`, imported from JSON, or declared without `as const`) now says what is missing when it is used. Its type, `WideSubcallResult`, is declared under the name `TypedResultRequiresAbiAsConst`, and its member for a function without outputs is `void` instead of `undefined`. `decimals.toUint(t.uint256)` on such a result used to give `'decimals' is possibly 'undefined'` followed by an error on a three-member union; it now gives `Property 'toUint' does not exist on type 'TypedResultRequiresAbiAsConst'`. Casting the result (`as Expr<'uint8'>`) works as before. Two type-level changes come with it: the result no longer fits a slot typed `… | undefined` (compare it with `=== undefined` or cast it), and an `s.read` or `s.simulate` call (or their `try` forms) whose parameter object is typed `any` now gets this result instead of `Tuple<TupleType>`.
