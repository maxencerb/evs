The ABI decoder emits smaller bytecode, which also runs cheaper for fixed-size arrays and deep struct chains. Results are unchanged, but the compiled bytes differ. Every offset and length bound (`x ≤ 2^64−1`) is now 3 bytes (`PUSH1 64 SHR`) instead of 10 (`PUSH8 0xff…ff LT`), at the same gas. That is about 6% of a decode-heavy script. A fixed-size word array (`uint256[N]`, `address[N]`, `uint8[N]`, …) is decoded with one bulk copy instead of an element loop, as a script argument, a call output, a struct member or an array element. For a full-word element (`uint256`, `int256`, `bytes32`) on `cancun` that copy is one `MCOPY`, about 3 gas per element. Otherwise it is an inline loop that also cleans narrow elements, about 70 gas per element. Both used to cost about 205. A `uint256[64]` argument now costs about 1.2k gas instead of 13.7k. Each level of nested dynamic structs used to cost more bytes than the one above it, because its base was re-derived through every enclosing offset word. The cost per level is now flat: a script that reads one field of a call returning seven nested `(uint256, string, …)` levels compiles to 1.2 KB instead of 1.8 KB, and the script costs about 14% less gas. A nested struct whose only member is a `string`, `bytes` or `uint256[]`-style array keeps the old lowering, which is cheaper for it.
