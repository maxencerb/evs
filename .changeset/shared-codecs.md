Scripts that repeat a struct or composite-array codec now emit it once: when several calls pass or return the same struct, struct array or fixed-size array, or the same struct is returned, encoded (`s.encode`, `s.keccak256`, `.eq()`) or thrown more than once, its encoder and decoder become shared subroutines that each site calls instead of inlining them (#95). Eight chained reads of an 8-field struct shrink from 6,264 to 2,138 runtime bytes (about 905k less gas in the default deployless mode), eight reads of an array of them from 9,494 to 2,792, four reads of a 3-deep nested struct from 10,613 to 3,860. A script that uses each codec once compiles exactly as before. Repeated `s.simulate` sites also share the decoding of their outputs, whatever their shape. Each shared codec call costs about 40-60 gas outside loops (small static structs and fixed-size arrays at the top of that range, struct arrays about 40; wide dynamic structs get cheaper than before; a read that shares both its encoder and its decoder pays it twice), and a use inside a loop only shares when that costs no extra gas. Decoded values, revert data and errors are unchanged, including `EvsDecodeError(site)`, which still names the failing call, and `explainRevert`; no API changes.
