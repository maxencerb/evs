`s.read` / `s.call` (and their `try*` forms) whose outputs are all words (`uint256`, `address`, `bool`, …) no longer keep their returndata in memory. It is copied straight into the output slots, so a loop of such reads (the multicall pattern) keeps a flat cost per iteration and no longer raises `LOOP_ALLOCATION`. The exception is a call whose arguments need encoder memory, which it still reserves on every call and still warns about (`s.read(f) (call-arg encode frames)`): arguments holding fixed-size arrays, arrays of structs, strings, bytes or arrays, or structs nested three or more dynamic levels deep. So does a call with a struct, a fixed-size array or an array of structs, strings, bytes or arrays as an argument that also takes a literal `string`/`bytes` or an all-literal word array (inline, or an `s.lit` hoisted before the loop): its arguments are encoded without folding literals into the calldata, so each such literal is first copied into a block allocated at the free pointer (`s.read(f) (staged call-arg literals)`). Bytecode changes for these call sites: each is a few bytes smaller and cheaper. Reads with a `string`, `bytes`, array or tuple output, and every `s.simulate`, still allocate and still warn.

`LOOP_ALLOCATION` and `ENV_FRAME_DEPENDENT` diagnostics now carry `site`, the id of the statement that raised them (its entry is in `compiled.sourceMap.sites`), so two warnings from look-alike statements can be told apart and one statement can be filtered out. `LOOP_ALLOCATION` messages name the builder call that allocates: a `struct: true` read reads `s.read(pair) struct` and a struct literal (a call argument, `s.lit`, a member, …) reads its type, `(uint256,address) literal`, instead of `s.tuple(…)`, `s.keccak256` over values reads `s.keccak256(…) encoded bytes` instead of `s.encode(…)`, `s.newArray` of a struct quotes the compact type (`s.newArray((uint256,address))`) instead of its JSON, and a call reads `s.read(symbol)` / `s.tryCall(quote)` / …. Each message now also says what to do (hoist the statement, or filter the warning on its code and site, re-checked after edits since site ids are positional). Also flags `s.simulate` sites with no outputs in a loop, which allocate too.
