pr: 180

Input that was recorded as something else, without a word, is now refused while the script is recorded, or read the way it was meant.

**A struct literal names every member.** A struct literal without a value for every member is refused instead of being sent with zeros. Outside `s.tuple`, a struct that was `undefined`, `{}`, short of members, or held an `undefined` member (a typo such as `config.recipent`) was recorded with those members at zero: `args: [config.params]` with `params` undefined sent an all-zero struct to the contract, and a missing `recipient` sent `address(0)`. A call argument, `s.lit`, `s.let`, `Cell.set`, `Field.set`, `MutArray.set`, an array element, an `s.fn` argument, an `s.throw` argument and a nested member now throw `EvsTypeError` (`TYPE_MISMATCH`) naming the position and the members without a value, as the types already required. A positional tuple literal needs one value per member. An unknown member name was already an error, and now names the member it resembles (`unknown member "recipent" — did you mean "recipient"?`). The `init` of `s.tuple(type, init?)` is unchanged at its top level: members left out there start at zero, as documented. A nested struct literal inside that `init` is a literal like any other and names every member.

**The members of a struct value are read the way JavaScript reads them**, in every position, `s.tuple`'s `init` included. A class instance whose members are getters on its prototype (every Svelte 5 `$state` class, a Lit element, a TC39 `accessor` field, any class with `get owner()`) and an `Object.create({ owner, amount })` record were recorded as an all-zero struct with no warning, because only own properties were read: `s.read({ …, args: [params] })` with `params` a Svelte `$state` class sent `address(0)` and `0`. Their members are now read, as in viem. A name found only on `Object.prototype` (`toString`, `valueOf`, …) is still no member, and neither is the `constructor` of a class. A `Map` throws `EvsTypeError` (`TYPE_MISMATCH`) instead of recording zeros: its entries are not properties, so pass `Object.fromEntries(map)`. `interpret()` reads a struct argument of the script by the same rule: it read own properties only, so `interpret(script, [new Params()])` threw `… .owner: expected a 0x-prefixed even-length hex string`.

**An array literal gives every element a value.** An array literal with a hole or an `undefined` element is refused, naming the index. A sparse array (`[a, , c]`, `new Array(n)`, a `delete`d element) used to throw a raw `TypeError: Cannot convert undefined to a BigInt` for a constant word array, and to record a zero, an empty string or a zeroed struct in the hole everywhere else (`[x, , 7n]` recorded `[x, 0, 7]`). Every array literal now throws `EvsTypeError` (`TYPE_MISMATCH`), for example `s.lit()[1]: the element is a hole (the array is sparse) — an array literal gives every element a value`.

**`s.throw` refuses values after its args** instead of dropping them: `s.throw(E, { a: 1n }, { a: 2n })` recorded the first record and ignored the second, and now throws `TYPE_MISMATCH`. A misspelled arg name is still refused, and now names the arg it resembles.

**`s.for` checks its range.** A key the range does not have was ignored, so `s.for({ from: 0n, until: 6n, setp: 2n }, …)` recorded a step of 1: it now throws `TYPE_MISMATCH` naming the key and, for a typo, the key it resembles. `step: null` was read as the default and is now refused (leave `step` out for a step of 1). A literal `step` of `0` recorded a loop that only ends by running out of gas: it now throws `LITERAL_RANGE`. A step computed at run time is recorded as before.
