`matchScriptError` types the handlers named `Panic`, `Error`, `EvsDecodeError` and `EvsInvalidCalldata`, and a `Panic` or `Error` handler now receives what the revert carries. A `Panic` handler used to be called with `{}` as its first argument, so `Panic: (p) => p.code` read `undefined`, and none of these handlers had inferred parameters. They are now optional, typed members of the handlers record, called as `(args, error)` like the handler of a declared error: `Panic: ({ code, kind, meaning }) => …`, `Error: ({ reason }) => …`, `EvsDecodeError: ({ site }) => …`. Without a handler these reverts reach `_`, as before. `kind` is new, on the handler's first argument and on the `Panic` arm that `decodeScriptError` returns: the panic code as one word to switch on (`'overflow'`, `'division-by-zero'`, `'out-of-bounds'`, `'out-of-memory'`, `'assert'`, `'enum-conversion'`, `'storage-encoding'`, `'empty-pop'`, `'zero-function'`, `'generic'`, or `'unknown'` for a code solc does not define), exported as `PanicKind`. A handler under any other key, a misspelled error name for example, is now a type error: nothing would call it. If a `Panic` or `Error` handler of yours read its second parameter for the decoded error, it keeps working.
