Tighten four places where the types accepted code that fails at recording or typed a result the runtime does not return. Two of them also reject code that worked before; the migration is noted on each.

- `toUint` / `toInt` are typed for numeric receivers only, like the other conversions: `addr.toUint(t.uint160)`, `flag.toUint(t.uint8)` or `word32.toInt(t.int256)` on an `address` / `bool` / `bytes32` / `string` / array `Expr` is now a compile error instead of a `TYPE_MISMATCH` thrown at recording. A `bytes32` goes through `asUint256()` first. **Migration:** the receiver needs a numeric static type, as for `add` or `lt`. A bare `Expr` (`Expr<EvsType>`) or a union mixing numeric and non-numeric types no longer type-checks even when its run-time value is numeric; cast it to the concrete type first (`(res as Expr<'uint8'>).toUint(t.uint256)`). Receivers typed `Expr<UintType | IntType>` or narrower, including generic ones, are unaffected.
- With a widened ABI (typed `Abi`, imported from JSON, or declared without `as const`), `s.read` / `s.call` / `s.simulate` and the `value` of their `try*` variants are typed `WideSubcallResult` (newly exported: `Expr | Tuple | readonly (Expr | Tuple)[] | undefined`), the shapes the recorder returns for no output, one output and several outputs. They were typed `readonly (Expr | Tuple)[]`, so `res[0]` or `const [x] = res` on a single-output function type-checked and then failed at recording. **Migration:** destructuring or indexing a multi-output result, which worked, now needs a cast to the known shape (`const [price, tick] = s.read({ …, functionName: 'slot0' }) as readonly [Expr<'uint160'>, Expr<'int24'>, Expr<'bool'>]`), and a single-output result a cast to its handle (`as Expr<'uint8'>`). Declaring the ABI `as const` avoids both.
- With an `as const` ABI that has no function in the verb's mutability bucket (an all-`nonpayable` ABI under `s.read`, an all-`view` ABI under `s.call`), `functionName` now accepts nothing, so the wrong verb is a compile error as it already was for mixed ABIs. `SubcallFunctionName` returns `never` there instead of viem's `string` fallback; a widened ABI still accepts any name.
- A script returning more than about 45 keys no longer overflows the type-instantiation depth: `client.readContract(...)` on it was typed `unknown`. The return record is now ordered with the same tail-recursive helper `t.struct` uses (checked up to 150 keys).
