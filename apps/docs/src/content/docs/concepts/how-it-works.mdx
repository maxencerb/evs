A script goes through four stages: your callback is recorded, the recording is compiled to
bytecode, a node executes it as one `eth_call`, and viem decodes the result.

<Pipeline />

Every output on this page comes from this script:

```ts title="script.ts"
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

export const supplyOf = evscript(
  { name: 'supplyOf', args: [t.address] },
  (s, token) => {
    const supply = s.read({
      address: token,
      abi: erc20Abi,
      functionName: 'totalSupply',
    });
    return s.return({ supply });
  },
);
```

## Record

`evscript` runs your callback once, without touching a chain. Each builder call appends a
statement to the IR (intermediate representation), the recorded program.

```ts
import { supplyOf } from './script';

const statements = supplyOf.ir.body;
```

The one `s.read` became one `call` statement:

```json
[
  {
    "k": "call",
    "target": 0,
    "fnAbi": {
      "name": "totalSupply",
      "selector": "0x18160ddd",
      "inputs": [],
      "outputs": [{ "name": "", "type": "uint256" }]
    },
    "args": [],
    "outs": [1],
    "mode": "strict",
    "site": 0
  }
]
```

The IR is frozen, plain JSON data. Because the callback only records, a native `if` never
branches on a chain value: see [Writing scripts](/guides/writing-scripts/).

## Compile

[`compile`](/reference/compile/) turns the IR into runtime bytecode, in five steps:

1. Validate the IR.
2. Remove dead code: statements whose result nothing reads.
3. Emit opcodes for each remaining statement.
4. Assemble the bytes and enforce the 24,576-byte code size limit.
5. [Verify the bytecode](/concepts/trust-and-testing/) before returning it.

[Compilation](/concepts/compilation/) goes through each step, what it removes and how long it
takes.

```ts
import { compile } from '@maxencerb/evs';
import { supplyOf } from './script';

const compiled = compile(supplyOf);
const listing = compiled.disassemble().format();
```

The `s.read` is a `STATICCALL`. When the callee reverts, the script reverts with the same data:

```txt
…
0x0060  6080        PUSH1 0x80
0x0062  51          MLOAD  ; target
0x0063  5a          GAS
0x0064  fa          STATICCALL  ; strict read totalSupply (site 0)
0x0065  610070      PUSH2 0x0070 → @call_ok_0
0x0068  57          JUMPI
0x0069  3d          RETURNDATASIZE
0x006a  5f          PUSH0
0x006b  5f          PUSH0
0x006c  3e          RETURNDATACOPY
0x006d  3d          RETURNDATASIZE
0x006e  5f          PUSH0
0x006f  fd          REVERT  ; bubble callee revert
…
```

:::caution[Unused results do not revert]
Dead-code removal also drops the checks of a removed statement. An overflowing `a.add(b)` whose
result you never use does not panic. Return the value, or pass it to a call or to
[`s.throw`](/reference/builder/throw/).
:::

## Execute

[`toViem()`](/reference/artifact/to-viem/) returns what `readContract` needs to send the
bytecode in one `eth_call`.

```ts title="client.ts" {10}
import { compile } from '@maxencerb/evs';
import { createPublicClient, http } from 'viem';
import { mainnet } from 'viem/chains';
import { supplyOf } from './script';

const client = createPublicClient({ chain: mainnet, transport: http() });
const compiled = compile(supplyOf);

export const result = await client.readContract({
  ...compiled.toViem(), // { abi, code }
  functionName: 'supplyOf',
  args: ['0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48'], // USDC
});
```

Inside the call, the script decodes its arguments, runs its statements and ABI-encodes the
returned values. The node discards every state change when the call ends.

The default mode is deployless: the node runs the code as a contract creation that it never
commits. With `toViem({ mode: 'stateOverride' })` the code sits at an address for the call
instead. [Executing scripts](/guides/execution/) compares the two.

## Decode

The first entry of `compiled.abi` describes the script as one `view` function:

```json
{
  "type": "function",
  "name": "supplyOf",
  "stateMutability": "view",
  "inputs": [{ "name": "arg0", "type": "address" }],
  "outputs": [
    {
      "name": "result",
      "type": "tuple",
      "components": [{ "name": "supply", "type": "uint256" }]
    }
  ]
}
```

The type of that ABI is literal, so viem infers `args` and the result without codegen.

```ts
import { result } from './client';

const supply: bigint = result.supply;
```

The ABI also lists the script's errors, which is how viem names a revert: see
[Errors & debugging](/guides/errors-and-debugging/).
