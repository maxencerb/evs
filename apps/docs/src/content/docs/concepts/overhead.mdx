A viem read encodes a call and sends it. evs also loads a compiler, records your script,
compiles it, and sends the bytecode with every call. This page measures each of those costs.

<OnceVsEveryCall />

## At a glance

For the [pool metadata example](/examples/pool-metadata/) and its eight reads:

| Cost | Paid | How much |
| --- | --- | --- |
| Load the library | once per page or process | 66 kB of JavaScript (brotli), 13 ms to import in Node |
| Record the script | once per script | 1.6 ms the first time, 0.02 ms warm |
| Compile it | once per script | 3.9 ms the first time, 0.13 ms warm |
| Encode and decode | every call | 0.015 ms |
| Send the bytecode | every call | a 3.8 kB request |
| Create the script on the node | every deployless call | 468,000 gas, against 50,000 in state-override mode |

:::note[One machine]
Every number comes from a MacBook Pro (Apple M5 Pro, 48 GB) running Node 24.22, evs 0.4.1 and
viem 2.57.1. Read them as orders of magnitude: [measure your own](#measure-your-own-script).
:::

## What runs, and when

| Step | Runs | What happens |
| --- | --- | --- |
| Import | once | The engine loads and evaluates the compiler. |
| Record | once per script | [`evscript`](/reference/evscript/) runs your callback. Each builder call checks its operands and appends a statement. |
| Compile | once per script | [`compile`](/reference/compile/) reads the whole program again for each pass. |
| Encode | every call | viem ABI-encodes the arguments and wraps them with the bytecode. |
| `eth_call` | every call | The node runs the script and discards it. In deployless mode it creates it first. |
| Decode | every call | viem decodes one result tuple. |

### Inside compile

No pass streams its output to the next. Each one reads the whole program before the next
starts.

| Form of the program | Read by |
| --- | --- |
| Statements | validate, dead code, validate again, slot assignment, emission, the source map, the warnings |
| Instructions | assemble, the stack check, the opcode checks. With `optimize`: fuse and peephole |
| Bytes | the jump-target scan, the hex encoding |

A default compile reads every statement over a dozen times, and every instruction about
five times. [Compilation](/concepts/compilation/#the-passes) explains and times each pass.

## Benchmarks

Four scripts, from one read to a hundred. Times are in milliseconds.

The first call in a fresh Node process, which is what an app pays:

| Script | Statements | Bytecode | Record | Compile |
| --- | --- | --- | --- | --- |
| [`supplyOf`](/concepts/how-it-works/): 1 read | 1 | 194 bytes | 1.0 | 2.8 |
| [Pool metadata](/examples/pool-metadata/): 8 reads | 10 | 1,196 bytes | 1.6 | 3.9 |
| [Balances](/examples/token-balances/): a loop | 15 | 586 bytes | 1.8 | 3.9 |
| 100 reads recorded by a JavaScript loop | 602 | 13,350 bytes | 2.9 | 12.3 |

The same calls once the JavaScript engine has optimized the compiler:

| Script | Record | Compile | Compile with `optimize` |
| --- | --- | --- | --- |
| `supplyOf` | 0.003 | 0.03 | 0.04 |
| Pool metadata | 0.02 | 0.13 | 0.20 |
| Balances | 0.01 | 0.07 | 0.13 |
| 100 reads | 0.31 | 1.77 | 3.10 |

- **You pay the first table.** An app records and compiles each script once, cold.
- **It warms up fast.** Compiling the pool metadata script a second time took 0.8 ms.
- **The import costs more than the compile.** Importing evs took 13 ms, after 66 ms for viem.
- **`optimize` adds 30% to 85%** to the compile: see
  [what it saves](/concepts/compilation/#what-it-saves).

## Compared with viem and wagmi

The same job, the eight reads of the pool metadata example, with and without evs.

### Bundle size

Sizes with brotli. evs adds about 65 kB to any of them, because it shares viem with the app.

| App | Alone | With evs | Added |
| --- | --- | --- | --- |
| viem, `createPublicClient` | 71.4 kB | 137.5 kB | 66.0 kB |
| `@wagmi/core` | 37.5 kB | 102.5 kB | 64.9 kB |
| wagmi with React | 106.8 kB | 171.9 kB | 65.1 kB |

### Each call

Without evs the job takes two multicalls: the token reads need addresses that the pool reads
return.

| | viem, 2 multicalls | evs, 1 call |
| --- | --- | --- |
| Round trips | 2 | 1 |
| CPU in your app | 0.089 ms | 0.015 ms |
| Request size | 1.8 kB + 1.9 kB | 3.8 kB |
| Response size | 1.8 kB + 1.7 kB | 0.8 kB |
| Against a local anvil | 0.38 ms | 0.16 ms |

- **The request carries the script.** Here it weighs as much as the two multicalls together.
- **The setup pays for itself.** A cold record and compile cost 5.5 ms, usually less than
  one round trip to a hosted node.
- **wagmi costs the same.** Its `readContract` hands the call to viem's: 0.015 ms measured.
- **wagmi's default config waits before a multicall.** Its `batch.multicall` setting sends
  each `readContracts` round through a timer: 1.3 ms per round in Node. A deployless call is
  never batched, so it leaves at once.

evs only adds cost when one multicall would do: see
[when not to use evs](/getting-started/why-evs/#when-not-to-use-evs).

## Reducing it

The examples share this script:

```ts title="script.ts"
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi, parseAbi } from 'viem';

const poolAbi = parseAbi([
  'function token0() view returns (address)',
  'function token1() view returns (address)',
]);

export const poolTokens = evscript(
  { name: 'poolTokens', args: [t.address] },
  (s, pool) => {
    const token0 = s.read({ address: pool, abi: poolAbi, functionName: 'token0' });
    const token1 = s.read({ address: pool, abi: poolAbi, functionName: 'token1' });
    const symbol0 = s.read({ address: token0, abi: erc20Abi, functionName: 'symbol' });
    const symbol1 = s.read({ address: token1, abi: erc20Abi, functionName: 'symbol' });
    return s.return({ token0, token1, symbol0, symbol1 });
  },
);
```

### Compile once

Record and compile at module scope, never inside a request handler or a component.

```ts title="compiled.ts" {5}
import { compile } from '@maxencerb/evs';
import { poolTokens } from './script';

// runs once, when the module is first imported
export const compiled = compile(poolTokens);
```

### Load it later

Import that module dynamically and the bundler moves evs out of your main bundle. The 66 kB
load the first time the function runs.

```ts {9}
import { createPublicClient, http, type Address } from 'viem';
import { mainnet } from 'viem/chains';

const client = createPublicClient({ chain: mainnet, transport: http() });

export async function readPool(pool: Address) {
  // evs is fetched, and the script compiled, on the first call
  // later calls reuse the module
  const { compiled } = await import('./compiled');
  return client.readContract({
    ...compiled.toViem(),
    functionName: 'poolTokens',
    args: [pool],
  });
}
```

### Precompile at build time

A compiled script is plain data: an ABI and a hex string. Write it to a file in a build
step, and the app ships neither the compiler nor the script.

```ts nocheck title="build.ts"
import { writeFileSync } from 'node:fs';
import { poolTokens } from './script';

const { abi, code } = poolTokens.compile().toViem();
const artifact = JSON.stringify({ abi, code }, null, 2);

writeFileSync(
  'pool-tokens.gen.ts',
  `export const poolTokens = ${artifact} as const;\n`,
);
```

The generated file, trimmed and reformatted here:

```ts title="pool-tokens.gen.ts"
export const poolTokens = {
  abi: [
    {
      type: 'function',
      name: 'poolTokens',
      stateMutability: 'view',
      inputs: [{ name: 'arg0', type: 'address' }],
      outputs: [
        {
          name: 'result',
          type: 'tuple',
          components: [
            { name: 'token0', type: 'address' },
            { name: 'token1', type: 'address' },
            { name: 'symbol0', type: 'string' },
            { name: 'symbol1', type: 'string' },
          ],
        },
      ],
    },
    // …the script's two error entries
  ],
  code: '0x6102bd80600a5f395ff3…', // 711 bytes
} as const;
```

The app imports only viem, and the call is typed as before:

```ts {8}
import { createPublicClient, http } from 'viem';
import { mainnet } from 'viem/chains';
import { poolTokens } from './pool-tokens.gen';

const client = createPublicClient({ chain: mainnet, transport: http() });

const result = await client.readContract({
  ...poolTokens,
  functionName: 'poolTokens',
  args: ['0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640'],
});
// result.symbol0: string
```

- **0.6 kB instead of 66 kB.** That is what the pool metadata artifact adds to a viem bundle.
- **`as const` keeps the types.** A `.json` import would widen the ABI and lose them.
- **Regenerate it** when the script changes, or when you change its
  [`evmVersion`](/guides/evm-targets/).
- **Debugging stays in your tooling.** [`explainRevert`](/reference/artifact/explain-revert/)
  and [`disassemble`](/reference/artifact/disassemble/) live on the compiled artifact.

### Skip the creation gas

A deployless call pays to create the script on every call. State-override mode does not, when
your provider supports it: see [choosing a mode](/guides/execution/#choosing-a-mode).

## Measure your own script

```ts nocheck
import { compile, evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const t0 = performance.now();
const supplyOf = evscript({ name: 'supplyOf', args: [t.address] }, (s, token) => {
  const supply = s.read({ address: token, abi: erc20Abi, functionName: 'totalSupply' });
  return s.return({ supply });
});
const t1 = performance.now();
const compiled = compile(supplyOf);
const t2 = performance.now();

console.log(`record ${(t1 - t0).toFixed(2)} ms, compile ${(t2 - t1).toFixed(2)} ms`);
console.log(`${(compiled.runtimeBytecode.length - 2) / 2} bytes`);
```

Run it at the top of a fresh process to get the first-call numbers.

## How this was measured

- **Timings.** Node 24.22. A first call is the median of 30 fresh processes. A warm one is
  the median of 2,000 runs after a warm-up (400 runs for the largest script).
- **Sizes.** esbuild 0.28, `--bundle --minify --format=esm`, then gzip level 9 and brotli
  quality 11. wagmi 3.7, `@wagmi/core` 3.6, React 19.
- **Download and start-up.** Headless Chromium loading the brotli bundle from a local server,
  with the DevTools network and CPU throttles. Each figure is the bundle with evs minus the
  same bundle without it.
- **Each call.** The CPU row replaces the network with a canned response. The anvil row is
  the median of 1,000 jobs against a local anvil 1.9.
- **Gas.** `eth_estimateGas` of the exact call viem sends, on anvil with Cancun rules.
