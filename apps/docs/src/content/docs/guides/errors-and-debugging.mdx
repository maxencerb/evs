A script fails in one of two places: while you build it, as a thrown error that points at your
line, or while it runs, as a revert you decode.

## Build-time errors

```ts {5}
import { evscript, EvsTypeError, t } from '@maxencerb/evs';

try {
  evscript({ name: 'bump', args: [t.uint8] }, (s, x) => {
    const y = x.add(300n); // throws here: 300 does not fit a uint8
    return s.return({ y });
  });
} catch (e) {
  if (e instanceof EvsTypeError) {
    e.code; // 'LITERAL_RANGE'
    e.message; // 'uint8 literal 300n is out of range [0, 255]'
  }
}
```

evs checks each builder call as it records it, so the error is thrown from your own line and
its stack trace points there. Every error has a stable `code`, listed under
[error codes](/reference/diagnostics/#error-codes).

| Class | Thrown for |
| --- | --- |
| `EvsTypeError` | a wrong type, an out-of-range literal, an operation on literals that always panics |
| `EvsStagingError` | an `Expr` used as a JavaScript value: `x + 1n`, a template string, `JSON.stringify(x)` |
| `EvsScopeError` | a value used outside the block or script that created it, a builder call after `s.return` |
| `EvsCompileError` | thrown by `compile()`: bytecode over 24,576 bytes, an unknown `evmVersion` |
| `EvsInternalError` | a bug in evs, not in your script: please report it |

`compile()` also reports non-fatal [warnings](/reference/diagnostics/#warnings), but only to
the [`onDiagnostic`](/reference/compile/#ondiagnostic-optional) callback you pass: it never
logs them.

## Reverts at run time

<RevertBubbling />

```ts {6, 8}
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const tokenInfo = evscript({ name: 'tokenInfo', args: [t.address] }, (s, token) => {
  // strict: if symbol() reverts, the script reverts with the same payload
  const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
  // try: if decimals() reverts, the script goes on with success = false and value = 0
  const d = s.tryRead({ address: token, abi: erc20Abi, functionName: 'decimals' });
  return s.return({ symbol, decimals: s.select(d.success, d.value, 18) });
});
```

A strict verb (`s.read`, `s.call`, `s.simulate`) passes the callee's revert through byte for
byte. A `try*` verb catches it.

A script reverts with one of these payloads:

| Payload | Cause |
| --- | --- |
| `Panic(uint256)` | a checked operation failed: an overflow, a division by zero, an index out of bounds. See [panic codes](/reference/diagnostics/#panic-codes) |
| An error you declared | your own [`s.throw`](/reference/builder/throw/) |
| `EvsDecodeError(uint256 site)` | a strict call returned data that does not decode |
| `EvsInvalidCalldata()` | the calldata does not match the script's function |
| The callee's payload | a contract called through a strict verb reverted |
| No data | see [failures without revert data](#failures-without-revert-data) |

## Decoding a revert with viem

Your declared errors are part of the script's ABI, so viem already names them when
`readContract` throws. `matchScriptError` turns the caught error into a typed switch.

```ts {26-31}
import { compile, evscript, matchScriptError, namedArg, t } from '@maxencerb/evs';
import { createPublicClient, http } from 'viem';
import { mainnet } from 'viem/chains';

const TooLow = t.error('TooLow', [namedArg('balance', t.uint256)]);

const guard = evscript(
  { name: 'guard', args: [t.uint256], errors: [TooLow] },
  (s, x) => {
    s.if(x.lt(10n), () => {
      s.throw(TooLow, { balance: x });
    });
    return s.return({ doubled: x.mul(2n) });
  },
);
const compiled = compile(guard);
const client = createPublicClient({ chain: mainnet, transport: http() });

try {
  await client.readContract({
    ...compiled.toViem(),
    functionName: 'guard',
    args: [5n],
  });
} catch (e) {
  const message = matchScriptError(compiled, e, {
    // `balance` is typed from the declaration
    TooLow: ({ balance }) => `balance too low: ${balance}`,
    // every other revert: a panic, a callee's error, no data
    _: (other) => `unexpected revert: ${other.name}`,
  });
}
```

- **Exhaustive.** Each declared error needs a handler, or the call does not typecheck. `_`
  takes every other revert.
- **Reverts only.** A network failure is rethrown, never sent to `_`.
- **As a value.** [`decodeScriptError`](/reference/utilities/decode-script-error/) returns
  the decoded revert for you to `switch` on.

## Explaining a revert

`explainRevert` maps a revert payload back to the sites, the places in your script, that can
produce it.

```ts {20}
import { compile, decodeScriptError, evscript, t } from '@maxencerb/evs';
import { createPublicClient, http, maxUint256 } from 'viem';
import { mainnet } from 'viem/chains';

const addOne = evscript({ name: 'addOne', args: [t.uint256] }, (s, x) =>
  s.return({ y: x.add(1n) }),
);
const compiled = compile(addOne);
const client = createPublicClient({ chain: mainnet, transport: http() });

try {
  await client.readContract({
    ...compiled.toViem(),
    functionName: 'addOne',
    args: [maxUint256],
  });
} catch (e) {
  const revert = decodeScriptError(compiled, e); // undefined when `e` is not a revert
  if (revert === undefined) throw e;
  const why = compiled.explainRevert(revert.raw);
  why.kind; // 'panic'
  why.message;
  // 'Panic(0x11): arithmetic overflow or underflow — 1 candidate site(s) in this
  //  script: checked add args.arg0 + 1 (uint256) — Panic 0x11 (site 1)'
}
```

:::caution[Sites are candidates, not proof]
A panic lists every site that can raise its code. A strict call also passes a callee's revert
through unchanged, so a `Panic` or an evs error can come from a contract you called.
:::

## Failures without revert data

Some failures leave nothing to decode.

- **A deployless limit.** The node refuses the call: a result or a payload that is too large,
  or a result that starts with `0xEF`.
  [`explainDeploylessError`](/reference/utilities/explain-deployless-error/) names the
  [limit](/guides/execution/#deployless-limits).
- **Out of gas, or a missing opcode.** Deployless mode shows a bare `execution reverted`. Run
  the call again with `toViem({ mode: 'stateOverride' })` to see the node's own error, and
  check the [EVM target](/guides/evm-targets/).
- **An unfunded `value`.** A `value` is paid from the script's balance. When it falls short,
  `s.call` reverts with no data and `s.simulate` with `EvsDecodeError`. Deployless mode cannot
  fund the script: use a `balance` in the state-override entry.

## Reading the bytecode

```ts {5}
import { compile, evscript, t } from '@maxencerb/evs';

const echo = evscript({ name: 'echo', args: [t.uint256] }, (s, x) => s.return({ x }));

const listing = compile(echo).disassemble().format();
```

```txt
0x0000  36          CALLDATASIZE
0x0001  610006      PUSH2 0x0006 → @dispatch
0x0004  57          JUMPI
0x0005  00          STOP  ; empty calldata: receive
@dispatch:
0x0006  5b          JUMPDEST  ; @dispatch
0x0007  60a0        PUSH1 0xa0  ; frameEnd
…
```

Each line holds the program counter, the raw bytes, the mnemonic, then a jump target or a note.
[`lookupPc`](/reference/utilities/disassemble/) finds the note for a pc taken from a node's
execution trace.
