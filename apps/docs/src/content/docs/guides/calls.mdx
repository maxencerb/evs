A script calls other contracts with three verbs, chosen by what the target function does to
state. Each has a `try*` variant that reports a failure instead of reverting.

<CallVerbs />

## Choosing a verb

| Verb | Try variant | Target function | The target's writes |
| --- | --- | --- | --- |
| [`s.read`](/reference/builder/read/) | [`s.tryRead`](/reference/builder/try-read/) | `view`, `pure` | are impossible (`STATICCALL`) |
| [`s.call`](/reference/builder/call/) | [`s.tryCall`](/reference/builder/try-call/) | `nonpayable`, `payable` | stay visible to later calls |
| [`s.simulate`](/reference/builder/simulate/) | [`s.trySimulate`](/reference/builder/try-simulate/) | `nonpayable`, `payable` | are rolled back, the result is kept |

- All six take the object viem's `readContract` takes: `address`, `abi`, `functionName`, `args`.
  Each verb's page lists the other options: `gas`, `struct`, `value`, `revertReturns`.
- The types enforce the verb: a `nonpayable` function under `s.read` does not compile.
- Nothing reaches the chain. The whole script runs inside one `eth_call`.

## Feeding one call into the next

`address` and every argument accept an `Expr`, so a call can use the result of an earlier one.
With viem alone, each step is a round trip.

```ts
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi, parseAbi } from 'viem';

const poolAbi = parseAbi(['function token0() view returns (address)']);

const token0 = evscript({ name: 'token0', args: [t.address] }, (s, pool) => {
  const token = s.read({ address: pool, abi: poolAbi, functionName: 'token0' });
  // token: Expr<'address'>, the target of the next two calls
  const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
  const reserve = s.read({
    address: token,
    abi: erc20Abi,
    functionName: 'balanceOf',
    args: [pool],
  });
  return s.return({ token, symbol, reserve });
});
```

A function with one output returns its handle. Several outputs come back as an array you
destructure, or as one struct with `struct: true`: see [`s.read`](/reference/builder/read/).

## Calling a function that is not view

Some functions only compute a result but are not marked `view`, and `s.read` rejects them. Call
them with `s.call`: a Uniswap quoter is the usual case.

```ts {11}
import { evscript, t } from '@maxencerb/evs';
import { parseAbi } from 'viem';

const quoterAbi = parseAbi([
  'function quoteExactInput(bytes path, uint256 amountIn) returns (uint256 amountOut)',
]);

const quote = evscript(
  { name: 'quote', args: [t.address, t.bytes, t.uint256] },
  (s, quoter, path, amountIn) => {
    const amountOut = s.call({
      address: quoter,
      abi: quoterAbi,
      functionName: 'quoteExactInput',
      args: [path, amountIn],
    });
    return s.return({ amountOut });
  },
);
```

Whatever the target writes stays visible to later calls, until the `eth_call` ends.

## Previewing a write

`s.simulate` runs a real write, hands you what it returned, then undoes it. Later calls see the
state from before.

```ts title="preview-withdraw.ts" {7}
import { evscript, t } from '@maxencerb/evs';
import { erc4626Abi } from 'viem';

export const previewWithdraw = evscript(
  { name: 'previewWithdraw', args: [t.address, t.uint256, t.address] },
  (s, vault, assets, owner) => {
    const shares = s.simulate({
      address: vault,
      abi: erc4626Abi,
      functionName: 'withdraw',
      args: [assets, owner, owner],
    });
    // rolled back: this is still the supply from before the withdrawal
    const supply = s.read({
      address: vault,
      abi: erc4626Abi,
      functionName: 'totalSupply',
    });
    return s.return({ shares, supply });
  },
);
```

With `s.call` in its place, `supply` would be the supply after the withdrawal.

## Defaults on failure

`s.read`, `s.call` and `s.simulate` revert the whole script with the target's revert data. A
`try*` verb returns `success` and `value` instead, and [`s.select`](/reference/builder/select/)
picks the default.

```ts {5-6}
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const decimals = evscript({ name: 'decimals', args: [t.address] }, (s, token) => {
  const d = s.tryRead({ address: token, abi: erc20Abi, functionName: 'decimals' });
  const value = s.select(d.success, d.value, 18); // 18 when the call fails
  return s.return({ value, known: d.success });
});
```

- `success` is `false` when the target reverts or returns data that does not decode.
- Use a `try*` verb for optional data, unknown tokens, or one bad item in a batch.
- Reverts and how to decode them are covered in
  [errors & debugging](/guides/errors-and-debugging/).

:::caution[Zero is also a real value]
After a failure, `value` is the zero of its type: `0`, `false`, an empty string. A call that
really returned `0` looks the same, so read `success` before you trust a zero.
:::

## What msg.sender the target sees

Whatever the verb, the target sees the script's own address as `msg.sender`. The vault above
lets only the owner or an approved spender withdraw, so the script must run at the owner's
address:

```ts {5}
import { previewWithdraw } from './preview-withdraw';

const owner = '0x1715a3E4A142d8b698131108995174F37aEBA10D';
const compiled = previewWithdraw.compile();
const params = compiled.toViem({ mode: 'stateOverride', sender: owner });
// spread `params` into client.readContract: every target sees msg.sender = owner
```

| `toViem` mode | `msg.sender` seen by targets |
| --- | --- |
| deployless (default) | the script's address, different for each compiled script |
| `stateOverride` | the override address |
| `stateOverride` with `sender` | `sender` |

:::caution[The script is the caller]
viem's `account` parameter sets who calls the script. It never changes the `msg.sender` of the
calls the script makes. See [executing scripts](/guides/execution/).
:::
