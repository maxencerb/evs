A script is a TypeScript callback that runs once, on your machine, and records statements. The
recorded program is what runs on-chain, inside one `eth_call`.

<BuildVsRun />

## Anatomy of a script

```ts
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const tokenMeta = evscript(
  { name: 'tokenMeta', args: [t.address, t.address] }, // 1
  (s, token, owner) => { // 2
    const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
    const balance = s.read({
      address: token,
      abi: erc20Abi,
      functionName: 'balanceOf',
      args: [owner],
    });
    return s.return({ symbol, balance }); // 3
  },
);
```

1. The definition names the script and lists its argument types.
2. The callback receives the builder `s`, then one handle per argument.
3. `s.return` names the outputs. viem decodes them as `{ symbol: string; balance: bigint }`.

## Declaring arguments

`args` is a list of types from the [`t` namespace](/reference/types/). Each one becomes a
parameter of the callback, in the same order.

```ts
import { evscript, namedArg, t } from '@maxencerb/evs';

const Query = t.struct({ token: t.address, owner: t.address });

const demo = evscript(
  { name: 'demo', args: [t.uint256, t.array(t.address), namedArg('query', Query)] },
  (s, amount, tokens, query) => {
    // amount: Expr<'uint256'>
    // tokens: Expr<'address[]'>
    // query:  Tuple with the fields `token` and `owner`
    return s.return({ amount, count: tokens.length(), owner: query.owner.get() });
  },
);
```

- A struct argument arrives as a [`Tuple`](/reference/builder/tuple/#tuple) handle. Every other
  argument is an [`Expr`](/reference/expr/).
- [`namedArg`](/reference/types/named-arg/) names an argument in the ABI. A bare type is named
  `arg0`, `arg1`, and so on.
- A script without arguments omits `args`. See [`evscript`](/reference/evscript/).

## What the callback receives

`s` is the [builder](/reference/builder/). Each `s.*` call records one statement and returns a
handle to its future result.

```ts
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const supply = evscript({ name: 'supply', args: [t.address] }, (s, token) => {
  const total = s.read({ address: token, abi: erc20Abi, functionName: 'totalSupply' });
  // total: Expr<'uint256'>. No call was made, and there is no bigint to look at.
  const next = total.add(1n); // records a checked addition
  return s.return({ total, next });
});
```

Using a handle where JS needs a value (`total + 1n`, a template string, `JSON.stringify`) throws
`EvsStagingError` on that line.

## Returning values

`s.return` takes a record of handles: an `Expr`, a `Tuple` or a
[`MutArray`](/reference/builder/new-array/#mutarray). Its keys become the names of the script's
outputs.

```ts
import { evscript, t } from '@maxencerb/evs';

const stats = evscript({ name: 'stats', args: [t.array(t.uint256)] }, (s, xs) => {
  const count = xs.length();
  return s.return({ count, first: xs.at(0n), all: xs });
});
// viem decodes the result as { count: bigint; first: bigint; all: readonly bigint[] }
```

- Call [`s.return`](/reference/builder/return/) once, at the top level, and return its result
  from the callback.
- It cannot sit inside an `s.if` branch or a loop. For a conditional result, set a
  [cell](/reference/builder/let/#cell) in the branch and return `cell.get()`.
- The record needs at least one key.

## Build time and run time

Plain JS runs while the callback records. A JS loop over a JS array unrolls: this script holds
two `balanceOf` calls and no loop.

```ts
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const TOKENS = [
  '0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48', // USDC
  '0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2', // WETH
] as const;

const watchlist = evscript({ name: 'watchlist', args: [t.address] }, (s, owner) => {
  const balances = s.newArray(t.uint256, TOKENS.length);
  for (const [i, token] of TOKENS.entries()) {
    const balance = s.read({
      address: token,
      abi: erc20Abi,
      functionName: 'balanceOf',
      args: [owner],
    });
    balances.set(i, balance);
  }
  return s.return({ balances });
});
```

| You write | It runs | It can depend on |
| --- | --- | --- |
| JS `if`, `for`, `.map()` | once, at build time | values your program already holds |
| `s.if`, `s.for`, `s.forEach`, `s.while`, `s.select` | on-chain, at run time | arguments and values read from the chain |

## Branching on a chain value

JS cannot branch on a handle. This script type-checks, compiles, and always returns `100`:

```ts {5}
import { evscript, t } from '@maxencerb/evs';

const wrong = evscript({ name: 'wrong', args: [t.bool] }, (s, stable) => {
  let fee = 3000;
  if (stable) fee = 100; // always taken: a handle is a truthy object
  return s.return({ fee: s.lit(t.uint24, fee) });
});
```

[`s.select`](/reference/builder/select/) and [`s.if`](/reference/builder/if/) record the branch
instead, so it is decided on-chain:

```ts {4}
import { evscript, t } from '@maxencerb/evs';

const right = evscript({ name: 'right', args: [t.bool] }, (s, stable) => {
  const fee = s.select(stable, s.lit(t.uint24, 100), 3000);
  return s.return({ fee });
});
```

:::caution[A handle is always truthy]
`if (handle)`, `handle && x` and `handle ? a : b` never throw. They take the truthy side at build
time, and the script returns a wrong result. The `typescript/strict-boolean-expressions` lint rule
reports them.
:::
