A compiled script runs inside one `eth_call` and is never deployed. `toViem()` returns the
`readContract` parameters for one of two modes: deployless (the default) or state override.

<ExecutionModes />

## Deployless (default)

```ts {14}
import { compile, evscript, t } from '@maxencerb/evs';
import { createPublicClient, erc20Abi, http } from 'viem';
import { mainnet } from 'viem/chains';

const tokenMeta = evscript({ name: 'tokenMeta', args: [t.address] }, (s, token) => {
  const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
  const decimals = s.read({ address: token, abi: erc20Abi, functionName: 'decimals' });
  return s.return({ symbol, decimals });
});

const client = createPublicClient({ chain: mainnet, transport: http() });

const meta = await client.readContract({
  ...compile(tokenMeta).toViem(), // { abi, code }
  functionName: 'tokenMeta',
  args: ['0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48'],
});
// meta: { symbol: string; decimals: number }
```

viem sends a plain `eth_call` with no `to`, which every provider accepts. The node runs it as
a contract creation, which is where the [deployless limits](#deployless-limits) come from.

## State override

```ts {19-20}
import { compile, evscript, t } from '@maxencerb/evs';
import { createPublicClient, erc20Abi, http } from 'viem';
import { mainnet } from 'viem/chains';

const myBalance = evscript({ name: 'myBalance', args: [t.address] }, (s, token) => {
  const balance = s.read({
    address: token,
    abi: erc20Abi,
    functionName: 'balanceOf',
    args: [s.env('caller')], // msg.sender
  });
  return s.return({ balance });
});

const client = createPublicClient({ chain: mainnet, transport: http() });

const { balance } = await client.readContract({
  // { abi, address, stateOverride }
  ...compile(myBalance).toViem({ mode: 'stateOverride' }),
  account: '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045', // the script's msg.sender
  functionName: 'myBalance',
  args: ['0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48'],
});
```

The third `eth_call` parameter places the script's code at an address for this call, and viem
calls that address like any contract.

- **Existing state stays.** The override replaces code only, not balance, nonce or storage.
  If you pass your own `address`, pick one with no state on the chain.
- **Multicall batching.** A client created with `batch: { multicall: true }` (the wagmi
  default) sends a state-override call that has no `account` through Multicall3, which
  becomes `msg.sender`. Pass `account`. Deployless calls are never batched.

## Sender mode

A contract your script calls sees the script's address as `msg.sender`, whatever `account` is.
The `sender` option installs the script at the address you pass, so the contract sees that one.

```ts {23}
import { compile, evscript, t } from '@maxencerb/evs';
import { createPublicClient, erc4626Abi, http } from 'viem';
import { mainnet } from 'viem/chains';

const preview = evscript(
  { name: 'preview', args: [t.address, t.uint256] },
  (s, vault, assets) => {
    // withdraw() burns msg.sender's shares, so it succeeds only as their owner
    const shares = s.simulate({
      address: vault,
      abi: erc4626Abi,
      functionName: 'withdraw',
      args: [assets, s.env('caller'), s.env('caller')],
    });
    return s.return({ shares });
  },
);

const client = createPublicClient({ chain: mainnet, transport: http() });
const owner = '0x1715a3E4A142d8b698131108995174F37aEBA10D'; // must hold vault shares

const { shares } = await client.readContract({
  ...compile(preview).toViem({ mode: 'stateOverride', sender: owner }),
  functionName: 'preview',
  args: ['0x83F20F44975D03b1b09e64809B757c47f942BEeA', 1_000_000n], // sDAI
});
```

- **One address.** `address` and `account` are both set to `sender`, so `s.env('caller')` and
  `s.env('address')` both return it.
- **The sender's code is replaced** for the call. An EOA has none to lose. A contract sender,
  a Safe for example, cannot answer callbacks such as `onERC721Received` during it.

## Choosing a mode

Use deployless unless you need something from the right column.

| | Deployless | State override |
| --- | --- | --- |
| Provider needs | plain `eth_call` | the third `eth_call` parameter |
| `msg.sender`, `s.env('caller')` | viem's wrapper contract, never your `account` | your `account` (zero address if omitted) |
| `address(this)`, `s.env('address')` | a CREATE2 address, different per script | `0xcD360FfAC9818c4396Aa6F4807EBfA72C4B3f530` (`DEFAULT_SCRIPT_ADDRESS`), or your `address` |
| `msg.sender` seen by called contracts | the script's CREATE2 address | the script address, or your `sender` |
| Script balance | cannot be funded | `balance` in the override entry |
| Result size, data size, gas | [limited](#deployless-limits) | no extra limit |

:::caution[Caller-relative reads need state override]
In deployless mode `balanceOf(s.env('caller'))` reads the balance of viem's wrapper
(`0xBd770416a3345F91E4B34576cb804a576fa48EB1` when no `account` is passed) and returns it
without an error. `compile()` reports each such read as an `ENV_FRAME_DEPENDENT`
[warning](/reference/diagnostics/#warnings).
:::

## Provider support

| Provider / node | Deployless (`to: null`) | State override (third `eth_call` parameter) |
| --- | --- | --- |
| geth, reth, anvil | yes | yes (documented; anvil verified in the integration suite) |
| QuickNode, publicnode | yes | yes (documented / empirically verified) |
| Alchemy, Infura | yes | **not documented** for `eth_call`: probe before relying on it |

Both modes run under the node's `eth_call` gas cap: 50M by default on geth (`--rpc.gascap`),
and hosted providers set their own. To pick the mode per provider at run time, pass a
`ToViemMode` value to [`toViem`](/reference/artifact/to-viem/).

## Deployless limits

The node applies its contract-creation rules to a deployless call. None of them apply in
state-override mode.

| Limit | In deployless mode | Node error, in viem's `details` |
| --- | --- | --- |
| Result size | the ABI-encoded result is at most 24,576 bytes (EIP-170): 765 elements for one `uint256[]` | `max code size exceeded` (geth), `CreateContractSizeLimit` (anvil) |
| `0xEF` prefix | the result's first byte is not `0xEF` (EIP-3541) | `invalid code: must not begin with 0xef` (geth), `CreateContractStartingWithEF` (anvil) |
| Data size | `398 + 128 + pad32(initBytecode) + pad32(calldata)` is at most 49,152 bytes (EIP-3860): about 48.6 KB of script and args, or roughly 1,500 array elements for a small script | `max initcode size exceeded` (geth and anvil) |
| Gas | about 75,000 + 220 per runtime byte + 200 per result byte extra: 1.6M for a 5 KB script that returns 2 KB | none: it counts toward the node's gas cap |

A limit never returns a wrong value: viem throws, usually `Missing or invalid parameters` or
`Transaction creation failed`.

- **Fix.** Switch to `toViem({ mode: 'stateOverride' })`. Without provider support for it,
  split a large array argument over several calls.
- **`0xEF` prefix.** Only a first returned value that is a `bytesN` (a hash: once in 256), a
  `uint256` of at least `0xEF·2^248` or an `int256` below `-2^252` can start with `0xEF`.
- **`0xEF` fix.** Return an `address`, a `bool` or a narrower integer first, or any dynamic
  value.
- **Detect.** `compile()` [warns](/reference/diagnostics/#warnings) about risky result
  shapes, and [`explainDeploylessError`](/reference/utilities/explain-deployless-error/)
  names the limit a failed call hit. `deploylessDataSize` measures the data size up front.

## Historical blocks

```ts {12, 14}
import { compile, evscript } from '@maxencerb/evs';
import { createPublicClient, http } from 'viem';
import { mainnet } from 'viem/chains';

const now = evscript({ name: 'now' }, (s) =>
  s.return({ timestamp: s.env('timestamp') }),
);
const client = createPublicClient({ chain: mainnet, transport: http() });

const { timestamp } = await client.readContract({
  // block 16,000,000 predates Shanghai
  ...compile(now, { evmVersion: 'paris' }).toViem(),
  functionName: 'now',
  blockNumber: 16_000_000n,
});
```

`blockNumber` and `blockTag` work in both modes, and every call the script makes reads that
block. The block also decides which opcodes exist, so compile for the fork active at that
block: see [EVM targets](/guides/evm-targets/).
