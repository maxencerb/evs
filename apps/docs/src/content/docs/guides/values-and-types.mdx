Every value in a script is a typed handle to something that exists only at run time. An `Expr` is
an immutable snapshot, while cells, arrays and structs hold the state you can change.

## Types

Every value has a Solidity type, written with the [`t` namespace](/reference/types/).

| You write | Type | Its handle |
| --- | --- | --- |
| `t.uint256`, `t.int24`, `t.address`, `t.bool`, `t.bytes32` | `'uint256'`, `'int24'`, … | `Expr` |
| `t.string`, `t.bytes` | `'string'`, `'bytes'` | `Expr` |
| `t.array(t.address)`, `t.array(t.uint256, 2)` | `'address[]'`, `'uint256[2]'` | `Expr` |
| `t.struct({ … })`, `t.tuple(…)` | an object listing the members | `Tuple` |

`t.uint256` is the string `'uint256'`, so a raw type string works wherever `t.*` does. The full
list is in the [primitives table](/reference/types/#primitives).

## Expr: a snapshot

An `Expr` stands for one value at one point of the program. Its methods return new `Expr`s.

```ts
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const supplyInfo = evscript({ name: 'supplyInfo', args: [t.address] }, (s, token) => {
  const supply = s.read({ address: token, abi: erc20Abi, functionName: 'totalSupply' });
  const half = supply.div(2n); // a new Expr<'uint256'>, `supply` is unchanged
  const large = half.gt(1_000_000n); // Expr<'bool'>
  const decimals = s.read({ address: token, abi: erc20Abi, functionName: 'decimals' });
  const wide = decimals.toUint(t.uint256); // Expr<'uint8'> to Expr<'uint256'>
  return s.return({ half, large, wide });
});
```

- [Arithmetic](/reference/expr/arithmetic/) is checked like Solidity: an overflow or a division
  by zero reverts.
- Types do not mix. Convert first, for example with
  [`toUint`](/reference/expr/conversions/#touint).
- Every method is listed in the [Expr reference](/reference/expr/).

## Literals

A plain JS value works wherever an `Expr` is expected. It takes the type of the `Expr` it meets.

```ts
import { evscript, t } from '@maxencerb/evs';

const lits = evscript({ name: 'lits', args: [t.uint256, t.address] }, (s, x, who) => {
  const sum = x.add(1n); // bigint
  const more = x.add(250); // number
  const isZero = who.eq('0x0000000000000000000000000000000000000000'); // 0x string
  const fees = s.lit(t.array(t.uint24), [100, 500, 3000]); // Expr<'uint24[]'>
  return s.return({ sum, more, isZero, fees });
});
```

- When nothing gives a literal its type, as in `s.return`, type it with
  [`s.lit`](/reference/builder/lit/).
- Literals are checked at build time: `s.lit(t.uint8, 300)` throws `EvsTypeError`.
- The JS value each type accepts is listed under [literals](/reference/expr/#literals).

## Cells

An `Expr` cannot change. A cell can: `s.let` creates it, `set` writes it, and `get` returns a
snapshot of its value at that point.

<CellSnapshots />

```ts
import { evscript, t } from '@maxencerb/evs';

const counter = evscript({ name: 'counter', args: [t.uint256] }, (s, start) => {
  const n = s.let(start); // Cell<'uint256'>
  const before = n.get(); // a snapshot
  n.set(n.get().add(1n));
  const after = n.get(); // a new snapshot
  return s.return({ before, after }); // start = 5 gives { before: 5n, after: 6n }
});
```

- `before` keeps its value after the `set`.
- A cell is not an `Expr`: read it with `get()` before you use it.
- A value leaves a branch or a loop body through a cell, an array slot or a struct field. See
  [`Cell`](/reference/builder/let/#cell) and [control flow](/guides/control-flow/).

## Arrays

Read an array `Expr` with `length()` and `at(i)`. Build a new array with `s.newArray`, then `set`
each slot.

```ts
import { evscript, t } from '@maxencerb/evs';

const doubled = evscript({ name: 'doubled', args: [t.array(t.uint256)] }, (s, xs) => {
  const out = s.newArray(t.uint256, xs.length()); // zero-filled MutArray
  s.forEach(xs, (x, i) => {
    out.set(i, x.mul(2n));
  });
  return s.return({ first: xs.at(0n), doubled: out });
});
```

- `at`, `get` and `set` are bounds-checked: an index past the end reverts with `Panic(0x32)`.
- An element can be any type, and arrays nest up to four levels: `t.array(t.array(t.string))`.
- See [`MutArray`](/reference/builder/new-array/#mutarray) and
  [bytes & arrays](/reference/expr/bytes-and-arrays/).

## Structs and tuples

A struct value is a `Tuple` handle with one field per member. Each field has `get` and `set`.

```ts
import { evscript, t } from '@maxencerb/evs';

const Position = t.struct({ owner: t.address, liquidity: t.uint128 });

const move = evscript({ name: 'move', args: [Position, t.address] }, (s, from, to) => {
  const liquidity = from.liquidity.get(); // Expr<'uint128'>
  const moved = s.tuple(Position, { owner: to, liquidity }); // a new struct
  from.liquidity.set(0n);
  return s.return({ from, moved }); // each decodes as { owner, liquidity }
});
```

- [`t.struct`](/reference/types/struct/) members are named and decode as an object.
  [`t.tuple`](/reference/types/tuple/) members are positional: reach them with `at(0)`.
- A struct returned by a call is the same handle. Where a struct is expected, pass a handle or
  an object literal.
- [`t.fromOutputs`](/reference/types/from-outputs/) derives a struct type from an ABI function.
- See [`Tuple`](/reference/builder/tuple/#tuple) and [`Field`](/reference/builder/tuple/#field).

:::caution[Arrays and structs are references]
A `MutArray` or `Tuple` handle points at memory. It is not a snapshot: `out.expr()` taken before
a `set` sees that write, and two handles to one struct share its fields.
:::
