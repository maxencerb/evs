evs runs reads that depend on earlier reads in one `eth_call`. A multicall needs one round trip
per dependency level.

<RoundTrips />

## The problem

To read the symbol of a pool's token, you first need the token's address.

```ts {16}
import { createPublicClient, erc20Abi, http, parseAbi } from 'viem';
import { mainnet } from 'viem/chains';

const client = createPublicClient({ chain: mainnet, transport: http() });
const poolAbi = parseAbi(['function token0() view returns (address)']);

// Round trip 1
const token0 = await client.readContract({
  address: '0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640',
  abi: poolAbi,
  functionName: 'token0',
});

// Round trip 2: this request cannot be built before the first one answers.
const symbol = await client.readContract({
  address: token0,
  abi: erc20Abi,
  functionName: 'symbol',
});
```

A multicall does not remove the wait. It encodes every call before the request leaves, so one
call's output cannot be another call's target.

## One script, one call

The same two reads as a script. Here `token0` is a placeholder for a value that exists only
inside the `eth_call`.

```ts {8}
import { evscript, t } from '@maxencerb/evs';
import { erc20Abi, parseAbi } from 'viem';

const poolAbi = parseAbi(['function token0() view returns (address)']);

export const symbolOf = evscript({ name: 'symbolOf', args: [t.address] }, (s, pool) => {
  const token0 = s.read({ address: pool, abi: poolAbi, functionName: 'token0' });
  const symbol = s.read({ address: token0, abi: erc20Abi, functionName: 'symbol' });
  return s.return({ token0, symbol });
});
```

evs compiles the script to EVM bytecode and viem runs it: see the
[quick start](/getting-started/quick-start/).

## Compared to the alternatives

| | Multicall | Helper contract | evs |
| --- | --- | --- | --- |
| Round trips for dependent reads | one per dependency level | one | one |
| A result feeds the next call | no | yes | yes |
| Loops and branches on chain data | no | yes | yes |
| Per-call failure handling | `allowFailure` | `try` / `catch` | [`s.tryRead`](/reference/builder/try-read/) |
| Language | TypeScript | Solidity | TypeScript |
| Deployment | uses the chain's Multicall3 | your contract, on each chain | none |
| Result types | per call | from the contract's ABI | inferred from the script |

## What you get

- **Types from viem.** `readContract` infers the arguments and the result object from the script.
- **Nothing to deploy.** The bytecode travels in the request. No contract, no transaction.
- **Runtime control flow.** [`s.if`](/reference/builder/if/), [`s.for`](/reference/builder/for/)
  and [`s.while`](/reference/builder/while/) branch and loop on chain data.
- **Solidity 0.8 semantics.** Arithmetic is checked, and a callee's revert reaches you unchanged.
- **Any block.** `blockNumber` works as in any `eth_call`. For an old block, compile for its
  [EVM target](/guides/evm-targets/).
- **Verified bytecode.** Every compile [checks its own output](/concepts/trust-and-testing/).

## When not to use evs

- **Writes.** A script is read-only: the node discards every state change when the call ends.
  Send a transaction.
- **Independent reads.** A multicall already batches them in one round trip.
- **A single read.** Call `readContract` directly.
- **A provider without state overrides**, when the script reads `msg.sender` or returns more
  than 24,576 bytes. See [deployless limits](/guides/execution/#deployless-limits) and
  [provider support](/guides/execution/#provider-support).
