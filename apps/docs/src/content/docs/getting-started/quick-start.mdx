description: Build a typed batch reader for Uniswap V3 pools — dependent on-chain reads collapsed into one deployless eth_call, fully inferred by viem end to end.
---

You will build a real batch reader: given a list of Uniswap V3 pool addresses and a user
address, fetch **each pool's** `fee`, its `slot0` (price/tick), and for **both of its tokens**
the `symbol`, `decimals`, and the user's balance — dozens of reads, several of them *dependent*
(a token read's target is the output of a pool read), all in a **single `eth_call`** that
returns one fully-typed array. You need
[`@maxencerb/evs` and `viem` installed](/getting-started/installation/) and an RPC URL.

## The script

The pool ABI is elided below for readability (hover any identifier to see its inferred type —
this page uses [Twoslash](https://twoslash.netlify.app/)). Everything else is the whole script:

```ts twoslash
import { arg, evscript, t } from '@maxencerb/evs';
import { erc20Abi } from 'viem';
// ---cut-start---
const uniswapV3PoolAbi = [
  { type: 'function', name: 'token0', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'address' }] },
  { type: 'function', name: 'token1', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'address' }] },
  { type: 'function', name: 'fee', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'uint24' }] },
  {
    type: 'function',
    name: 'slot0',
    stateMutability: 'view',
    inputs: [],
    outputs: [
      { name: 'sqrtPriceX96', type: 'uint160' },
      { name: 'tick', type: 'int24' },
      { name: 'observationIndex', type: 'uint16' },
      { name: 'observationCardinality', type: 'uint16' },
      { name: 'observationCardinalityNext', type: 'uint16' },
      { name: 'feeProtocol', type: 'uint8' },
      { name: 'unlocked', type: 'bool' },
    ],
  },
] as const;
// ---cut-end---
// Derive the slot0 struct type straight from the ABI — no re-typing its 7 fields.
const Slot0 = t.fromOutputs(uniswapV3PoolAbi, 'slot0');
//    ^?

// Compose the output shape from structs; a struct member can itself be a struct.
const TokenMetadata = t.struct({
  address: t.address,
  symbol: t.string,
  decimals: t.uint8,
  userBalance: t.uint256,
});
const PoolMetadata = t.struct({
  token0: TokenMetadata,
  token1: TokenMetadata,
  fee: t.uint24,
  slot0: Slot0,
});

export const poolsData = evscript(
  { name: 'poolsData', args: [t.array(t.address), t.address] },
  (s, pools, user) => {
    // A reusable, typed subroutine: one token's metadata. `arg(name, type)` names its params.
    const tokenMetadata = s.fn(
      'tokenMetadata',
      [arg('token', t.address), arg('owner', t.address)] as const,
      (token, owner) =>
        s.tuple(TokenMetadata, {
          address: token,
          symbol: s.call({ address: token, abi: erc20Abi, functionName: 'symbol' }),
          decimals: s.call({ address: token, abi: erc20Abi, functionName: 'decimals' }),
          userBalance: s.call({ address: token, abi: erc20Abi, functionName: 'balanceOf', args: [owner] }),
        }),
    );

    // One output row per input pool, collected in a counted loop.
    const metadata = s.newArray(PoolMetadata, pools.length());
    s.for({ type: t.uint256, from: 0n, until: pools.length() }, (i) => {
      const pool = pools.at(i);
      const token0 = s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'token0' });
      const token1 = s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'token1' });
      metadata.set(
        i,
        s.tuple(PoolMetadata, {
          // DEPENDENT reads: token0/token1 are outputs of the pool read above, and become
          // the *target* of the token reads inside tokenMetadata — on-chain, in one call.
          token0: tokenMetadata(token0, user),
          token1: tokenMetadata(token1, user),
          fee: s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'fee' }),
          // `struct: true` decodes slot0's 7 named outputs into one Slot0-shaped object.
          slot0: s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'slot0', struct: true }),
        }),
      );
    });

    return s.return({ metadata });
  },
);
```

Each line is plain TypeScript that *records* what the script will do; the callback runs once,
at recording time. The pieces, in order:

- **`t.fromOutputs(abi, 'slot0')`** derives a struct type from a function's ABI outputs, so
  `Slot0` matches `slot0()` exactly without hand-retyping its seven fields — see
  [deriving types from an ABI](/guides/values-and-types/#deriving-types-from-an-abi).
- **`t.struct({ ... })`** builds composite types, and a member can itself be a struct
  (`PoolMetadata.token0` is a `TokenMetadata`) — see
  [composite types](/guides/values-and-types/#composite-types-structs-and-tuples).
- **`s.fn(name, [arg(...)], body)`** defines a reusable typed subroutine compiled once and
  called twice here (token0 and token1) — see [user functions](/guides/functions/).
- **`s.call({ ..., struct: true })`** decodes a multi-output getter into one named object
  instead of a positional tuple — see [calls](/guides/calls/#decoding-multiple-outputs-into-a-struct).
- **`s.newArray` + `s.for`** collect one row per pool, the multicall-style fan-out — see
  [control flow](/guides/control-flow/).

The dependency that makes this a script and not a multicall: `token0` is the **output** of the
pool read and the **address** of the token reads. Multicall must know every target up front, so
it cannot express this in one round trip; evs records the chain and runs it on-chain. See
[why evs](/getting-started/why-evs/).

## Compile and run it

`compile()` validates the recorded script and returns a frozen artifact; spread `toViem()` into
a plain viem `readContract` and add the `functionName` and typed `args`:

```ts twoslash
import { arg, evscript, t } from '@maxencerb/evs';
import { createPublicClient, erc20Abi, http } from 'viem';
// ---cut-start---
const uniswapV3PoolAbi = [
  { type: 'function', name: 'token0', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'address' }] },
  { type: 'function', name: 'token1', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'address' }] },
  { type: 'function', name: 'fee', stateMutability: 'view', inputs: [], outputs: [{ name: '', type: 'uint24' }] },
  {
    type: 'function',
    name: 'slot0',
    stateMutability: 'view',
    inputs: [],
    outputs: [
      { name: 'sqrtPriceX96', type: 'uint160' },
      { name: 'tick', type: 'int24' },
      { name: 'observationIndex', type: 'uint16' },
      { name: 'observationCardinality', type: 'uint16' },
      { name: 'observationCardinalityNext', type: 'uint16' },
      { name: 'feeProtocol', type: 'uint8' },
      { name: 'unlocked', type: 'bool' },
    ],
  },
] as const;
const Slot0 = t.fromOutputs(uniswapV3PoolAbi, 'slot0');
const TokenMetadata = t.struct({
  address: t.address,
  symbol: t.string,
  decimals: t.uint8,
  userBalance: t.uint256,
});
const PoolMetadata = t.struct({ token0: TokenMetadata, token1: TokenMetadata, fee: t.uint24, slot0: Slot0 });
const poolsData = evscript(
  { name: 'poolsData', args: [t.array(t.address), t.address] },
  (s, pools, user) => {
    const tokenMetadata = s.fn(
      'tokenMetadata',
      [arg('token', t.address), arg('owner', t.address)] as const,
      (token, owner) =>
        s.tuple(TokenMetadata, {
          address: token,
          symbol: s.call({ address: token, abi: erc20Abi, functionName: 'symbol' }),
          decimals: s.call({ address: token, abi: erc20Abi, functionName: 'decimals' }),
          userBalance: s.call({ address: token, abi: erc20Abi, functionName: 'balanceOf', args: [owner] }),
        }),
    );
    const metadata = s.newArray(PoolMetadata, pools.length());
    s.for({ type: t.uint256, from: 0n, until: pools.length() }, (i) => {
      const pool = pools.at(i);
      const token0 = s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'token0' });
      const token1 = s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'token1' });
      metadata.set(
        i,
        s.tuple(PoolMetadata, {
          token0: tokenMetadata(token0, user),
          token1: tokenMetadata(token1, user),
          fee: s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'fee' }),
          slot0: s.call({ address: pool, abi: uniswapV3PoolAbi, functionName: 'slot0', struct: true }),
        }),
      );
    });
    return s.return({ metadata });
  },
);
// ---cut-end---
const code = poolsData.compile();
// code.runtimeBytecode — the script body (EIP-170: at most 24,576 bytes, enforced)
// code.abi            — literal-typed ABI: the 'poolsData' view function plus the two evs error entries

const client = createPublicClient({ transport: http('https://eth.merkle.io') });

const result = await client.readContract({
  ...code.toViem(), // { abi, code } — one deployless eth_call, nothing deployed
  functionName: 'poolsData',
  args: [
    ['0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640'], // USDC/WETH 0.05% pool (mainnet)
    '0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640',
  ],
});
```

## The typed result

`result` is inferred entirely from the script — no `as const`, no codegen. Each `s.return` key
becomes a named output; structs become objects, `tuple[]`/arrays become arrays, and every leaf
maps by its ABI type (`address` → `` `0x${string}` ``, `uint8`/`uint24`/`int24` → `number`,
`uint256` → `bigint`, `bool` → `boolean`):

```ts
type Result = {
  metadata: readonly {
    token0: { address: `0x${string}`; symbol: string; decimals: number; userBalance: bigint };
    token1: { address: `0x${string}`; symbol: string; decimals: number; userBalance: bigint };
    fee: number;
    slot0: {
      sqrtPriceX96: bigint;
      tick: number;
      observationIndex: number;
      observationCardinality: number;
      observationCardinalityNext: number;
      feeProtocol: number;
      unlocked: boolean;
    };
  }[];
};
```

## What just happened

Nothing was deployed and no transaction was sent. `toViem()` hands viem the script's init
bytecode under the `code` parameter; viem issues a single plain two-parameter `eth_call` (no
`to`) in which the script is instantiated counterfactually, runs — decoding your arguments,
looping over the pools, performing the dependent reads with values flowing between them
on-chain — and returns one ABI-encoded result that viem decodes into the typed array above.
Everything inside the call is discarded by the node afterwards. A state-override mode with a
deterministic script address also exists; see [execution](/guides/execution/).
