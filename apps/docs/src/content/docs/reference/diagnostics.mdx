Every error class and code evs throws, the warnings `compile()` reports, and the panics and
built-in errors a script reverts with.

| When | What you get | Where to look |
| --- | --- | --- |
| while the `evscript` callback runs | a thrown `EvsError`, at the offending line | [Error codes](#error-codes) |
| in `compile()` | a thrown `EvsError`, or a warning | [Error codes](#error-codes), [Warnings](#warnings) |
| when the script runs | a revert | [Panic codes](#panic-codes), [Built-in errors](#built-in-errors) |

## Error classes

Every error evs throws extends `EvsError` and carries a `code`.

```ts {8-11}
import { evscript, EvsError, t } from '@maxencerb/evs';

try {
  evscript({ name: 'bump', args: [t.uint8] }, (s, x) => {
    return s.return({ y: x.add(300n) }); // 300 does not fit uint8
  });
} catch (error) {
  if (error instanceof EvsError) {
    error.name; // 'EvsTypeError'
    error.code; // 'LITERAL_RANGE'
    error.message; // 'uint8 literal 300n is out of range [0, 255]'
  }
}
```

| Class | Thrown when | Codes |
| --- | --- | --- |
| `EvsError` | the base class of the five below. On its own, only for a precompiled script without debug data | `DEBUG_DATA_MISSING` |
| `EvsStagingError` | a handle is used as a plain JS value | `STAGING_MISUSE` |
| `EvsTypeError` | a type, literal, ABI or error declaration is wrong, or a function gets a malformed input | `TYPE_MISMATCH`, `LITERAL_RANGE`, `CERTAIN_PANIC`, `UNSUPPORTED_V0`, `ABI_SHAPE`, `ERROR_DECL`, `ERROR_UNDECLARED` |
| `EvsScopeError` | a value, cell, loop control or builder is used where it is not valid | `SCOPE_VIOLATION`, `FOREIGN_HANDLE`, `RECORDING_CLOSED` |
| `EvsCompileError` | the whole program breaks a limit, or an option is not supported | `COMPILE_LIMIT`, `EVM_VERSION`, `UNSUPPORTED_V0` |
| `EvsInternalError` | an evs invariant failed. The message contains `bug in evs, please report` | `INTERNAL` |

| Property | Type | Holds |
| --- | --- | --- |
| `code` | `EvsErrorCode` | one of the [error codes](#error-codes). Stable, safe to compare |
| `name` | `string` | the class name, such as `'EvsTypeError'` |
| `message` | `string` | what went wrong and how to fix it |
| `stack` | `string`, optional | for a recording error, it includes your line: the error is thrown inside your callback |

## Error codes

| Code | Class | Thrown when |
| --- | --- | --- |
| `STAGING_MISUSE` | `EvsStagingError` | a handle is used as a JS value: `x + 1`, a template literal, `JSON.stringify(x)` |
| `TYPE_MISMATCH` | `EvsTypeError` | an operand or argument has the wrong type, or an evs function receives a malformed input |
| `LITERAL_RANGE` | `EvsTypeError` | a literal, or an `interpret()` argument, does not fit its type: out of range, not a safe integer, hex of the wrong length |
| `CERTAIN_PANIC` | `EvsTypeError` | an operation on literals would always panic: an overflow, a division by zero, a conversion that does not fit, an array length of 2^32 or more |
| `SCOPE_VIOLATION` | `EvsScopeError` | a value or cell is used after its `s.if` or loop block ended, an `s.fn` body uses an outer value, a `LoopCtl` is used outside its loop, or `s.return` is not at the top level |
| `FOREIGN_HANDLE` | `EvsScopeError` | a handle comes from another script, or from a second copy of evs |
| `RECORDING_CLOSED` | `EvsScopeError` | a builder method is called after `s.return` |
| `UNSUPPORTED_V0` | `EvsTypeError`, `EvsCompileError` | a type nests arrays more than 4 levels deep or has a static size of 2^32 bytes or more. From `compile()`: its structs and arrays nest too deep for the EVM stack |
| `ABI_SHAPE` | `EvsTypeError` | ABI material is malformed: an invalid or repeated name, an empty `s.return`, a `functionName` the ABI does not have, an ambiguous overload |
| `ERROR_DECL` | `EvsTypeError` | an error declaration is invalid: a bad, reserved or duplicate name, a selector clash, a script named like one of its errors |
| `ERROR_UNDECLARED` | `EvsTypeError` | `s.throw` gets an error that is not in the script's `errors` |
| `COMPILE_LIMIT` | `EvsCompileError` | the runtime bytecode is over 24,576 bytes, or `interpret()` goes over `maxSteps` |
| `EVM_VERSION` | `EvsCompileError` | `evmVersion` is not `'paris'`, `'shanghai'` or `'cancun'` |
| `DEBUG_DATA_MISSING` | `EvsError` | [`explainRevert()`](/reference/precompiled/explain-revert/) or `debug()` is called on a precompiled script [hydrated](/reference/precompiled/hydrate/) without a `debug` loader. The promise rejects with it |
| `INTERNAL` | `EvsInternalError` | an evs invariant or bytecode check failed: a bug in evs, unless you loaded the IR with [`deserializeIr`](/reference/utilities/serialize-ir/) or passed a `peephole` hook |

Reserved error names, rejected with `ERROR_DECL`: `Error`, `Panic`, `EvsDecodeError`,
`EvsInvalidCalldata`, `empty`, `unknown` and `_`.

## Warnings

`compile()` never logs. A warning is passed to the `onDiagnostic` option, and dropped when you do
not set it.

```ts {8}
import { compile, evscript, type EvsDiagnostic } from '@maxencerb/evs';

const whoami = evscript({ name: 'whoami', args: [] }, (s) => {
  return s.return({ me: s.env('caller') });
});

const warnings: EvsDiagnostic[] = [];
compile(whoami, { onDiagnostic: (warning) => warnings.push(warning) });

warnings[0]?.code; // 'ENV_FRAME_DEPENDENT'
warnings[0]?.site; // 0
```

| Code | Raised when | What to do |
| --- | --- | --- |
| `LOOP_ALLOCATION` | a statement in a loop allocates memory, such as `s.newArray`, `s.tuple`, a struct or array literal, `s.encode`, `.slice`, any `s.simulate`, or a call that returns a `string`, `bytes`, array or struct | memory and its gas grow on every iteration. Move the statement out of the loop when you can |
| `LARGE_FRAME` | the memory the script reserves for its values is over 32,768 bytes | memory gas grows quadratically. Split the script |
| `ENV_FRAME_DEPENDENT` | the script reads `s.env('caller')`, `s.env('address')` or its own balance, or sends `value` with a call | the result differs between the two `toViem()` modes. See [Executing scripts](/guides/execution/) |
| `DEPLOYLESS_RESULT_PREFIX` | the result can start with byte `0xEF`: its first value is a `bytesN`, or a `uint256` or `int256` evs cannot bound | deployless mode rejects such a result. See [deployless limits](/guides/execution/#deployless-limits) |
| `DEPLOYLESS_RESULT_SIZE` | the encoded result is always over 24,576 bytes | every deployless call fails. Use state-override mode, or return less |

A warning is an `EvsDiagnostic`:

| Field | Type | Holds |
| --- | --- | --- |
| `severity` | `'warning'` | always `'warning'`: a hard failure throws instead |
| `code` | string | one of the five codes above |
| `message` | `string` | what was found and what to do |
| `site` | `number`, optional | the id of the statement that raised it, in `compiled.sourceMap.sites` |

`site` is set on `LOOP_ALLOCATION`, `ENV_FRAME_DEPENDENT` and `DEPLOYLESS_RESULT_PREFIX`. It is
absent on `LARGE_FRAME` and `DEPLOYLESS_RESULT_SIZE`, and on a `DEPLOYLESS_RESULT_PREFIX` about
a script argument.

### Which results raise DEPLOYLESS_RESULT_PREFIX

Only the first returned value matters, or its first member for a struct or fixed array, and
only when the whole result is static.

| First returned value | Warns |
| --- | --- |
| a `bytesN`, such as a hash | always |
| a `uint256` or `int256` from an argument, a call output or a hash | yes |
| a length, a counter, a timestamp, a balance, a widened narrower integer | no |
| an `address`, a `bool`, an integer narrower than 256 bits | no |
| anything, when some returned value is dynamic (`string`, `bytes`, `T[]`) | no |

### Ignoring a warning

There is no suppression switch. Filter in your callback, by `code`, or by `code` and `site` for
one statement.

```ts {20-22}
import { compile, evscript, t, type EvsDiagnostic } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const symbols = evscript(
  { name: 'symbols', args: [t.array(t.address)] },
  (s, tokens) => {
    const total = s.let(t.uint256, 0n);
    s.forEach(tokens, (token) => {
      const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
      total.set(total.get().add(symbol.length()));
    });
    return s.return({ total: total.get() });
  },
);

const warnings: EvsDiagnostic[] = [];
const ignored: EvsDiagnostic[] = [];

const compiled = compile(symbols, {
  onDiagnostic: (warning) => {
    (warning.code === 'LOOP_ALLOCATION' ? ignored : warnings).push(warning);
  },
});

compiled.sourceMap.sites.find((site) => site.id === ignored[0]?.site)?.detail;
// 'decoding symbol() returndata'
```

:::caution[Site ids move when you edit the script]
Statements are numbered in recording order. Add one before the statement you filtered, and the
same `site` now silences a different statement. Check the filter again after each edit.
:::

## Panic codes

A failed check reverts with Solidity's `Panic(uint256)`: the selector `0x4e487b71`, then the
code as one 32-byte word. A script raises four codes itself.

| Code | Meaning | Raised by |
| --- | --- | --- |
| `0x11` | arithmetic overflow or underflow | [`add`, `sub`, `mul`, `pow`](/reference/expr/arithmetic/); signed `div` of the minimum value by -1; [`mulDiv`, `mulDivRoundingUp`](/reference/expr/full-precision/) when the result does not fit `uint256`; [`toUint`, `toInt`, `asAddress`](/reference/expr/conversions/) when the value does not fit the target |
| `0x12` | division or modulo by zero | `div`, `mod`, `addmod`, `mulmod`, `mulDiv`, `mulDivRoundingUp` with a zero divisor, modulus or denominator |
| `0x32` | array index out of bounds | [`.at(i)`, `.byteAt(i)`, `.slice(start, end)`](/reference/expr/bytes-and-arrays/), and `get` or `set` on a [`MutArray`](/reference/builder/new-array/#mutarray) |
| `0x41` | allocation too large (out of memory) | [`s.newArray`](/reference/builder/new-array/) with a length of 2^32 or more |

`s.read`, `s.call` and `s.simulate` pass a called contract's revert through unchanged, so a
script can also revert with a code that only the contract raises:

| Code | Meaning |
| --- | --- |
| `0x00` | generic compiler panic |
| `0x01` | assertion failure (assert) |
| `0x21` | invalid enum conversion |
| `0x22` | corrupted storage byte array |
| `0x31` | pop on an empty array |
| `0x51` | call to a zero-initialized internal function |

Each meaning is the `meaning` text that
[`decodeScriptError`](/reference/utilities/decode-script-error/) returns. Any other code reads
`unknown panic code`.

- **No check, no panic.** A check that cannot fail is not compiled: dividing by a nonzero
  literal has no `0x12` check.
- **Unused results do not panic.** An operation whose result nothing reads is removed with its
  check. See [`dce`](/reference/utilities/dce/).
- **Wrapping never panics.** The [wrapping operations](/reference/expr/wrapping/) and wrapping
  conversions skip the check on purpose.

## Built-in errors

Two custom errors belong to evs. Both are in every script's `abi`, so viem decodes them by name.

| Error | Selector | Raised when |
| --- | --- | --- |
| `EvsInvalidCalldata()` | `0xf43fed56` | the calldata is not a call to the script's function: wrong selector, truncated, or malformed arguments |
| `EvsDecodeError(uint256 site)` | `0x20cf27b7` | `s.read`, `s.call` or `s.simulate` gets returndata it cannot decode. `site` is the call's id in `compiled.sourceMap.sites` |

`EvsDecodeError` is also raised by an [`s.call`](/reference/builder/call/) with `revertReturns`
that returns instead of reverting, and by an `s.simulate` whose `value` the script cannot pay.

The two entries are exported as `EVS_ERROR_ABI`:

```ts
import { EVS_ERROR_ABI } from '@maxencerb/evs';

EVS_ERROR_ABI[0]; // { type: 'error', name: 'EvsInvalidCalldata', inputs: [] }
EVS_ERROR_ABI[1].name; // 'EvsDecodeError'
EVS_ERROR_ABI[1].inputs; // [{ name: 'site', type: 'uint256' }]
```
