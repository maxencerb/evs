Every error class and code evs throws, the warnings `compile()` reports, and the panics and
built-in errors a script reverts with.

| When | What you get | Where to look |
| --- | --- | --- |
| while the `evscript` callback runs | a thrown `EvsError`, at the offending line | [Error codes](#error-codes) |
| in `compile()` | a thrown `EvsError`, or a warning | [Error codes](#error-codes), [Warnings](#warnings) |
| when the script runs | a revert | [Panic codes](#panic-codes), [Built-in errors](#built-in-errors) |

## Error classes

Every error evs throws extends `EvsError` and carries a `code`.

```ts {8-11}
import { evscript, EvsError, t } from '@maxencerb/evs';

try {
  evscript({ name: 'bump', args: [t.uint8] }, (s, x) => {
    return s.return({ y: x.add(300n) }); // 300 does not fit uint8
  });
} catch (error) {
  if (error instanceof EvsError) {
    error.name; // 'EvsTypeError'
    error.code; // 'LITERAL_RANGE'
    error.message; // 'uint8 literal 300n is out of range [0, 255]'
  }
}
```

| Class | Thrown when | Codes |
| --- | --- | --- |
| `EvsError` | the base class of the five below. On its own, only for a precompiled script without debug data | `DEBUG_DATA_MISSING` |
| `EvsStagingError` | a handle is used as a plain JS value | `STAGING_MISUSE` |
| `EvsTypeError` | a type, literal, ABI or error declaration is wrong, or a function gets a malformed input | `TYPE_MISMATCH`, `LITERAL_RANGE`, `CERTAIN_PANIC`, `UNSUPPORTED_V0`, `ABI_SHAPE`, `ERROR_DECL`, `ERROR_UNDECLARED` |
| `EvsScopeError` | a value, cell, loop control or builder is used where it is not valid | `SCOPE_VIOLATION`, `FOREIGN_HANDLE`, `RECORDING_CLOSED` |
| `EvsCompileError` | the whole program breaks a limit, or an option is not supported | `COMPILE_LIMIT`, `EVM_VERSION`, `UNSUPPORTED_V0` |
| `EvsInternalError` | an evs invariant failed. The message contains `bug in evs, please report` | `INTERNAL` |

| Property | Type | Holds |
| --- | --- | --- |
| `code` | `EvsErrorCode` | one of the [error codes](#error-codes). Stable, safe to compare |
| `name` | `string` | the class name, such as `'EvsTypeError'` |
| `message` | `string` | what went wrong and how to fix it |
| `stack` | `string`, optional | for a recording error, it includes your line: the error is thrown inside your callback |

## Error codes

| Code | Class | Thrown when |
| --- | --- | --- |
| `STAGING_MISUSE` | `EvsStagingError` | a handle is used as a JS value: `x + 1`, a template literal, `JSON.stringify(x)` |
| `TYPE_MISMATCH` | `EvsTypeError` | an operand or argument has the wrong type, or an evs function receives a malformed input, such as an invalid IR that was [deserialized](/reference/utilities/serialize-ir/) or written by hand. Also a struct or array literal with a member or element left out, and a callback that is [not synchronous](/guides/writing-scripts/#callbacks-are-synchronous) |
| `LITERAL_RANGE` | `EvsTypeError` | a literal, or an `interpret()` argument, does not fit its type: out of range, not a safe integer, hex of the wrong length. Also a literal [`s.for`](/reference/builder/for/#step-optional) step of `0` |
| `CERTAIN_PANIC` | `EvsTypeError` | an operation on literals would always panic: an overflow, a division by zero, a conversion that does not fit, an array length of 2^32 or more |
| `SCOPE_VIOLATION` | `EvsScopeError` | a value or cell is used after its `s.if` or loop block ended, an `s.fn` body uses an outer value, a `LoopCtl` is used outside its loop, or `s.return` is not at the top level |
| `FOREIGN_HANDLE` | `EvsScopeError` | a handle comes from another script, or from a second copy of evs |
| `RECORDING_CLOSED` | `EvsScopeError` | a builder method is called after `s.return` |
| `UNSUPPORTED_V0` | `EvsTypeError`, `EvsCompileError` | a type nests arrays more than 4 levels deep or has a static size of 2^32 bytes or more, or blocks nest [more than 256 levels deep](/reference/builder/if/#nesting-limit). From `compile()`: its structs and arrays nest too deep for the EVM stack |
| `ABI_SHAPE` | `EvsTypeError` | ABI material is malformed: an invalid or repeated name, an empty `s.return`, a `functionName` the ABI does not have, an ambiguous overload. From `compile()`: a script that uses `s.simulate` and whose name and arguments give the [reserved selector](/reference/compile/#errors) |
| `ERROR_DECL` | `EvsTypeError` | an error declaration is invalid: a bad, reserved or duplicate name, a selector clash, a script named like one of its errors |
| `ERROR_UNDECLARED` | `EvsTypeError` | `s.throw` gets an error that is not in the script's `errors` |
| `COMPILE_LIMIT` | `EvsCompileError` | the runtime bytecode is over 24,576 bytes, or `interpret()` goes over `maxSteps` |
| `EVM_VERSION` | `EvsCompileError` | `evmVersion` is not `'paris'`, `'shanghai'` or `'cancun'` |
| `DEBUG_DATA_MISSING` | `EvsError` | [`explainRevert()`](/reference/precompiled/explain-revert/) or `debug()` is called on a precompiled script [hydrated](/reference/precompiled/hydrate/) without a `debug` loader. The promise rejects with it |
| `INTERNAL` | `EvsInternalError` | an evs invariant or bytecode check failed: a bug in evs, unless you passed a `peephole` hook |

Reserved error names, rejected with `ERROR_DECL`: `Error`, `Panic`, `EvsDecodeError`,
`EvsInvalidCalldata`, `empty`, `unknown` and `_`.

## Warnings

`compile()` never logs. A warning is passed to the `onDiagnostic` option, and dropped when you do
not set it.

```ts {8}
import { compile, evscript, type EvsDiagnostic } from '@maxencerb/evs';

const whoami = evscript({ name: 'whoami', args: [] }, (s) => {
  return s.return({ me: s.env('caller') });
});

const warnings: EvsDiagnostic[] = [];
compile(whoami, { onDiagnostic: (warning) => warnings.push(warning) });

warnings[0]?.code; // 'ENV_FRAME_DEPENDENT'
warnings[0]?.key; // 's.env(caller)'
```

| Code | Raised when | What to do |
| --- | --- | --- |
| `LOOP_ALLOCATION` | a statement in a loop allocates memory, such as `s.newArray`, `s.tuple`, a struct or array literal, `s.encode`, `.slice`, any `s.simulate`, or a call that returns a `string`, `bytes`, array or struct | memory and its gas grow on every iteration. Move the statement out of the loop when you can |
| `LARGE_FRAME` | the memory the script reserves for its values is over 32,768 bytes | memory gas grows quadratically. Split the script |
| `ENV_FRAME_DEPENDENT` | the script reads `s.env('caller')`, `s.env('address')` or its own balance, or sends `value` with a call. One warning for each of these, however many statements do it | the result differs between the two `toViem()` modes. See [Executing scripts](/guides/execution/) |
| `DEPLOYLESS_RESULT_PREFIX` | the result can start with byte `0xEF`: its first value is a `bytesN`, a `uint256` or `int256` evs cannot bound, or a literal that starts with `0xEF` | deployless mode rejects such a result. See [deployless limits](/guides/execution/#deployless-limits) |
| `DEPLOYLESS_RESULT_SIZE` | the encoded result is always over 24,576 bytes | every deployless call fails. Use state-override mode, or return less |

A warning is an `EvsDiagnostic`:

| Field | Type | Holds |
| --- | --- | --- |
| `severity` | `'warning'` | always `'warning'`: a hard failure throws instead |
| `code` | string | one of the five codes above |
| `message` | `string` | what was found and what to do |
| `key` | `string`, optional | what the warning is about, as a text that survives edits. See [keys](#keys) |
| `site` | `number`, optional | the `id` of the first statement in `sites` |
| `sites` | `{ id, key }[]`, optional | the statements the warning covers, as in `compiled.sourceMap.sites` |

`LARGE_FRAME` and `DEPLOYLESS_RESULT_SIZE` are about the whole script: they have none of the
three optional fields. A `DEPLOYLESS_RESULT_PREFIX` about a script argument has a `key` and no
statement.

### Which results raise DEPLOYLESS_RESULT_PREFIX

Only the first returned value matters, or its first member for a struct or fixed array, and
only when the whole result is static.

| First returned value | Warns |
| --- | --- |
| a literal, of any type | only when its first byte is `0xEF`: every deployless call then fails |
| any other `bytesN`, such as a hash | always |
| a `uint256` or `int256` from an argument, a call output or a hash | yes |
| a length, a counter, a timestamp, a balance, a widened narrower integer | no |
| an `address`, a `bool`, an integer narrower than 256 bits | no |
| anything, when some returned value is dynamic (`string`, `bytes`, `T[]`) | no |

### Ignoring a warning

There is no suppression switch. Filter in your callback: on `code` for a whole kind of warning,
on `code` and `key` for one of them.

```ts {16,20}
import { compile, evscript, t, type EvsDiagnostic } from '@maxencerb/evs';
import { erc20Abi } from 'viem';

const symbols = evscript(
  { name: 'symbols', args: [t.array(t.address)] },
  (s, tokens) => {
    const total = s.let(t.uint256, 0n);
    s.forEach(tokens, (token) => {
      const symbol = s.read({ address: token, abi: erc20Abi, functionName: 'symbol' });
      total.set(total.get().add(symbol.length()));
    });
    return s.return({ total: total.get() });
  },
);

const acknowledged = new Set(['LOOP_ALLOCATION s.read(symbol)#0']);
const warnings: EvsDiagnostic[] = [];

compile(symbols, {
  onDiagnostic: (warning) => {
    if (!acknowledged.has(`${warning.code} ${warning.key}`)) warnings.push(warning);
  },
});

warnings.length; // 0
```

Print `warning.key` with the message, and copy it into the list once you have read the warning.

### Keys

A `key` names what a warning is about. With `code`, it identifies one warning of a script.

| Code | `key` | Example |
| --- | --- | --- |
| `LOOP_ALLOCATION` | the statement that allocates | `s.read(symbol)#0` |
| `ENV_FRAME_DEPENDENT` | what is read from the frame, or the call that sends `value` | `s.env(caller)`, `s.env(address)`, `s.balance(s.env(address))`, `s.call(deposit)` |
| `DEPLOYLESS_RESULT_PREFIX` | the returned value at byte 0 of the result | `s.return(total)`, `s.return(position.amounts[0])` |

An `ENV_FRAME_DEPENDENT` warning covers every statement that reads the same thing. Its `sites`
lists them.

```ts {8-9}
import { compile, evscript, t, type EvsDiagnostic } from '@maxencerb/evs';

const mine = evscript({ name: 'mine', args: [t.address] }, (s, owner) =>
  s.return({ isCaller: s.env('caller').eq(owner), caller: s.env('caller') }),
);

const warnings: EvsDiagnostic[] = [];
compile(mine, { onDiagnostic: (warning) => warnings.push(warning) });
// one warning for the two reads

warnings[0]?.key; // 's.env(caller)'
warnings[0]?.sites;
// [
//   { id: 0, key: 's.env(caller)#0' },
//   { id: 2, key: 's.env(caller)#1' },
// ]
```

A statement's key has up to three parts, as in `quote/s.read(symbol)#1`:

| Part | Holds |
| --- | --- |
| `quote/` | the [`s.fn`](/reference/builder/fn/) whose body holds the statement. Absent in the script body |
| `s.read(symbol)` | the label: what the statement is |
| `#1` | how many statements with the same label come before it in the same function |

The label comes from the statement itself:

| Statement | Label | Example |
| --- | --- | --- |
| `s.read`, `s.call`, `s.simulate` and their `try` forms | the verb and the function name | `s.tryCall(quote)` |
| a call of an `s.fn` | the name you gave it | `quote()` |
| `s.env` | the verb and what it reads | `s.env(timestamp)` |
| `s.balance`, `s.codeSize`, `s.codeHash` | the verb | `s.balance` |
| `s.throw` | the verb and the error | `s.throw(Stale)` |
| a literal | `literal` and its type | `literal(string)` |
| a new array: `s.newArray`, an array literal | `array` and its type | `array(address[])` |
| a new struct or tuple: `s.tuple`, a struct literal, a `struct: true` call | `tuple` and its member types | `tuple(uint112,uint112)` |
| a conversion | `convert` and the type it gives | `convert(uint256)` |
| `s.encode`, and the encoding inside `s.keccak256(a, b)` or an `eq` of two arrays or structs | `encode` | `encode` |
| `s.encodePacked` | `encodePacked` | `encodePacked` |
| anything else | its name in the [recorded program](/reference/artifact/#ir) | `add`, `index`, `cellget`, `while` |

A key does not change when you:

- add, remove or reorder statements with another label, in the same function or elsewhere
- change `optimize` or `evmVersion`
- write a statement whose result nothing reads:
  [dead-code elimination](/reference/utilities/dce/) drops it from the bytecode, and it still
  counts
- upgrade evs: a release that moves the key of a warning says so in its notes

:::caution[One edit moves a key]
A statement with the same label, added or removed earlier in the same function, shifts the
index of the ones after it. A second `s.read` of `symbol` placed above the first turns
`s.read(symbol)#0` into `s.read(symbol)#1`, and the acknowledged warning prints again.
:::

Loops record statements of their own: `s.for` and `s.forEach` keep a counter, with a `cellget`,
an `lt` and an `add` per loop. They count like the ones you write, so a loop added above moves
keys such as `add#3`. No warning has one of those labels: they only show in the site table and
in [`explainRevert`](/reference/artifact/explain-revert/).

`site` is another name of the same statement: its position among all the statements of the
script. It moves with any edit above it, so filter on `key`.

## Panic codes

A failed check reverts with Solidity's `Panic(uint256)`: the selector `0x4e487b71`, then the
code as one 32-byte word. A script raises four codes itself.

| Code | `kind` | Meaning | Raised by |
| --- | --- | --- | --- |
| `0x11` | `'overflow'` | arithmetic overflow or underflow | [`add`, `sub`, `mul`, `pow`](/reference/expr/arithmetic/); signed `div` of the minimum value by -1; [`mulDiv`, `mulDivRoundingUp`](/reference/expr/full-precision/) when the result does not fit `uint256`; [`toUint`, `toInt`, `asAddress`](/reference/expr/conversions/) when the value does not fit the target |
| `0x12` | `'division-by-zero'` | division or modulo by zero | `div`, `mod`, `addmod`, `mulmod`, `mulDiv`, `mulDivRoundingUp` with a zero divisor, modulus or denominator |
| `0x32` | `'out-of-bounds'` | array index out of bounds | [`.at(i)`, `.byteAt(i)`, `.slice(start, end)`](/reference/expr/bytes-and-arrays/), and `get` or `set` on a [`MutArray`](/reference/builder/new-array/#mutarray) |
| `0x41` | `'out-of-memory'` | allocation too large (out of memory) | [`s.newArray`](/reference/builder/new-array/) with a length of 2^32 or more |

`s.read`, `s.call` and `s.simulate` pass a called contract's revert through unchanged, so a
script can also revert with a code that only the contract raises:

| Code | `kind` | Meaning |
| --- | --- | --- |
| `0x00` | `'generic'` | generic compiler panic |
| `0x01` | `'assert'` | assertion failure (assert) |
| `0x21` | `'enum-conversion'` | invalid enum conversion |
| `0x22` | `'storage-encoding'` | corrupted storage byte array |
| `0x31` | `'empty-pop'` | pop on an empty array |
| `0x51` | `'zero-function'` | call to a zero-initialized internal function |

[`decodeScriptError`](/reference/utilities/decode-script-error/) returns the `kind` and the
`meaning` of a code. Switch on `kind`, show `meaning`. Any other code has the kind `'unknown'`
and reads `unknown panic code`.

- **No check, no panic.** A check that cannot fail is not compiled: dividing by a nonzero
  literal has no `0x12` check.
- **Unused results do not panic.** An operation whose result nothing reads is removed with its
  check. See [`dce`](/reference/utilities/dce/).
- **Wrapping never panics.** The [wrapping operations](/reference/expr/wrapping/) and wrapping
  conversions skip the check on purpose.

## Built-in errors

Two custom errors belong to evs. Both are in every script's `abi`, so viem decodes them by name.

| Error | Selector | Raised when |
| --- | --- | --- |
| `EvsInvalidCalldata()` | `0xf43fed56` | the calldata is not a call to the script's function: wrong selector, truncated, or malformed arguments |
| `EvsDecodeError(uint256 site)` | `0x20cf27b7` | `s.read`, `s.call` or `s.simulate` gets returndata it cannot decode. `site` is the call's id in `compiled.sourceMap.sites` |

`EvsDecodeError` is also raised by an [`s.call`](/reference/builder/call/) with `revertReturns`
that returns instead of reverting, and by an `s.simulate` whose `value` the script cannot pay.

`site` is a position: it changes when a statement is added above the call. To log or match the
call, use the [`key`](#keys) that [`explainRevert`](/reference/artifact/explain-revert/) gives
for it.

The two entries are exported as `EVS_ERROR_ABI`:

```ts
import { EVS_ERROR_ABI } from '@maxencerb/evs';

EVS_ERROR_ABI[0]; // { type: 'error', name: 'EvsInvalidCalldata', inputs: [] }
EVS_ERROR_ABI[1].name; // 'EvsDecodeError'
EVS_ERROR_ABI[1].inputs; // [{ name: 'site', type: 'uint256' }]
```

## Reading a failure

| Tool | Use it to |
| --- | --- |
| [`decodeScriptError`](/reference/utilities/decode-script-error/) | turn a caught error into a typed value |
| [`matchScriptError`](/reference/utilities/match-script-error/) | run one handler per declared error |
| [`compiled.explainRevert`](/reference/artifact/explain-revert/) | find the statement in your script that reverted |
| [`precompiled.explainRevert`](/reference/precompiled/explain-revert/) | do the same in a client that ships no compiler |
| [`explainDeploylessError`](/reference/utilities/explain-deployless-error/) | recognize a deployless limit, which is not a revert |
| [`explainUnsupportedOpcode`](/reference/utilities/explain-unsupported-opcode/) | recognize a script compiled for a fork the chain does not have, which is not a revert either |
