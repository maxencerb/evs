Reads a value from the execution environment, such as the script's address, its caller or the
current block.

## Usage

```ts {5-7}
import { evscript } from '@maxencerb/evs';

const blockInfo = evscript({ name: 'blockInfo' }, (s) =>
  s.return({
    chainId: s.env('chainid'),
    blockNumber: s.env('blocknumber'),
    timestamp: s.env('timestamp'),
  }),
);
```

### Comparing with the block time

The result is an ordinary `Expr`, so it takes every operator.

```ts {4}
import { evscript, t } from '@maxencerb/evs';

const isExpired = evscript({ name: 'isExpired', args: [t.uint256] }, (s, deadline) => {
  const expired = s.env('timestamp').gt(deadline);
  return s.return({ expired });
});
```

### Reading for the caller

`s.env('caller')` is your `account` only in state-override mode.

```ts {10,19,23}
import { compile, evscript, t } from '@maxencerb/evs';
import { createPublicClient, erc20Abi, http } from 'viem';
import { mainnet } from 'viem/chains';

const myBalance = evscript({ name: 'myBalance', args: [t.address] }, (s, token) => {
  const balance = s.read({
    address: token,
    abi: erc20Abi,
    functionName: 'balanceOf',
    args: [s.env('caller')],
  });
  return s.return({ balance });
});

const client = createPublicClient({ chain: mainnet, transport: http() });

const { balance } = await client.readContract({
  ...compile(myBalance).toViem({
    mode: 'stateOverride',
  }),
  functionName: 'myBalance',
  args: ['0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48'],
  account: '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045',
});
```

:::caution[`caller` and `address` depend on the execution mode]
In the default deployless mode, `'caller'` is viem's wrapper contract and `'address'` is a
temporary address you do not choose. Neither is your `account`. In state-override mode,
`'caller'` is the `account` you pass. See [Executing scripts](/guides/execution/).
:::

## Returns

`Expr<'address'>` for `'address'` and `'caller'`, `Expr<'uint256'>` for the other kinds

The value, read when the script runs.

## Parameters

### kind

- **Type:** `'address' | 'caller' | 'timestamp' | 'blocknumber' | 'chainid'`

Which value to read.

| Kind | Type | Solidity | Value |
| --- | --- | --- | --- |
| `'address'` | `Expr<'address'>` | `address(this)` | the address the script runs at |
| `'caller'` | `Expr<'address'>` | `msg.sender` | who called the script |
| `'timestamp'` | `Expr<'uint256'>` | `block.timestamp` | the block's time, in seconds |
| `'blocknumber'` | `Expr<'uint256'>` | `block.number` | the block's number |
| `'chainid'` | `Expr<'uint256'>` | `block.chainid` | the chain id |

```ts {4}
import { evscript } from '@maxencerb/evs';

const chain = evscript({ name: 'chain' }, (s) => {
  const chainId = s.env('chainid'); // Expr<'uint256'>
  return s.return({ chainId });
});
```

## Behavior

- **Block values.** `'timestamp'`, `'blocknumber'` and `'chainid'` are the same in every
  execution mode. They belong to the block the call runs against.
- **Mode warning.** `compile` reports an `ENV_FRAME_DEPENDENT`
  [warning](/reference/diagnostics/#warnings) for each `'caller'` or `'address'` read.
- **Arbitrum block number.** `'blocknumber'` is the `NUMBER` opcode. On Arbitrum it is an
  approximate L1 block number: read `ArbSys(0x64).arbBlockNumber()` for the L2 block.

## Errors

Thrown while the callback records, at the offending line:

| Error | When |
| --- | --- |
| `EvsTypeError` (`TYPE_MISMATCH`) | `kind` is not one of the five kinds |
